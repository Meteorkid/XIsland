## 目标与实施边界

先确保审批含义准确、升级可恢复、用户配置不丢失，再改善数据与长期运行体验。采用现有架构内的局部修复，不把测试通过视为真实客户端或 Windows 实机验收。保留现有未提交改动。

同仓库另一聊天贡献了更新回滚、额度真实单位、审批参数展示和 Windows 发布基础；这些改动已合并到本轮隔离验证。当前主线完成问答工具身份、插件认领保护、Windows 坏缓存启动恢复、历史清理与空闲图标。另一聊天遗留的 CODEX_HOME 防误写实现也已补齐。

当前完成度按工作包分别记录：C1 的操作/心跳/资源基线已建立，端到端交互延迟未验；C2 后台 I/O 与取消已实现并回归；C3 增量保存、共享快照和容量边界已实现，生产检查点改为串行后台事务，5 万事件主线程模拟回调 p95 1.08 ms；总事务 p95 261.68 ms 不等于主线程阻塞；C4 自适应轮询、隐藏暂停、果冻与无障碍标签通过代码/Timer 测试；C5 中英文深浅主题 20 张快照、浏览器交互、固定存储版本 8 小时长稳及部分原生交互通过；旁白朗读、实际帧率、多屏仍待验。后续 UI/测量仪器修复的完整回归通过，不宣称最终 GUI 版本已整版重复长稳。

下一步顺序：

1. **已完成长稳终态核验**：28806.605 秒、25140 个唯一事件、exitCode=0，SQLite 完整性及导出逐项匹配；原二进制和当时 332 个源文件 hash 一致。资源曲线及 Mach 时基校准已归档。
2. **C5-1 旁白**：原生工具恢复后重试仍超时，未取得朗读证据；用户暂时无法人工测试，不重复催促。等待稳定工具或用户可测试时验证实际朗读、焦点次序和失效请求保护。旁白已确认关闭，ProMotion 保持原值。
3. **C5-2/C5-3 帧率与多屏**：旧 60Hz 导出已恢复，但操作仅部分覆盖、连续帧归属未证实；新 ProMotion 记录到时后保存超时，判为采样失败。下一次先通过短录制保存/导出预检，再以逐操作时间戳完整采样，核对进程/图层归属和时间映射；不把 frame lifetime 或 VSYNC 当作 App FPS。多屏需真实外接设备，目前仍只检测到内建屏，待验证不同 DPI、拔插、全屏及焦点。
4. 三项适用出口形成证据后关闭 C，再执行下表 D1。当前仅更新阶段 D 计划，不将其原生验收标为已开始或完成。

阶段出口：固定 Release 构建与样本测量、可靠提交、取消保护和资源曲线；目标交互 p95<100ms。现有主线程模拟回调达标，但不能替代剩余原生朗读/帧率/多屏证据。
