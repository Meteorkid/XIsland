# 会话精确跳转与移出后收起修复

发行说明：本批实现已纳入 2.0.10 发行源码，见 [2.0.10 更新说明](../releases/2.0.10.md)。以下保留开发与隔离验收阶段的记录；客户端实机验收边界没有因发布而改变。

日期：2026-10-24。分支：`codex/session-navigation-hover-20261024`，基于 `15c993e`。本轮仅实现与验证，未提交、发布或替换正式 XIsland，版本号仍为 2.0.9。

## 用户要求与实际原因

用户要求点击任务后进入对应聊天/标签页；鼠标停在展开面板或岛内不收起，只在离开两者后按设置延时收起。

原跳转函数没有使用会话 ID，获取窗口失败后仍会激活软件、抬起全部窗口或打开工作目录，并将这些动作视为成功。hook 到达时捕获的前台窗口编号也不是会话归属证明。列表、详情和 Agent Flow 的部分入口在跳转结果返回前已经收起或清除“完成未查看”。

原自动收起包含独立的无操作计时、完成后延迟任务和鼠标离开策略：前两者不检查鼠标，后者从展开时刻计算时间，导致长时间停留后离开立即收起。

## 实现

### 精确会话路由

| 客户端 | 新定位方式 | 边界 |
| --- | --- | --- |
| Codex 桌面 | `codex://threads/<UUID>` | 严格匹配 `codex-UUID`，拒绝哈希兜底、非法 ID 和子任务后缀 |
| Cursor | `cursor://anysphere.cursor-deeplink/agent?id=<conversation_id>` | 从原生 Cursor 会话 ID 构造，完整编码为一个查询值 |
| WorkBuddy | `workbuddy://chat/<native session_id>` | 严格解码现有 `workbuddy-<base64>`，仅覆盖已核验的本地命令 hook |
| iTerm2 | unique ID 或 TTY | 唯一匹配后选中分屏会话、标签和窗口，没有匹配不激活其他窗口 |
| Apple Terminal | TTY | 唯一匹配后选中对应标签，不使用目录名或前台窗口猜测 |
| WezTerm | 明确 pane ID | 执行 `cli activate-pane --pane-id` 并确认命令成功退出 |
| kitty | 明确 window ID | 执行 `@ focus-window --match id:N` 并确认命令成功退出 |
| 其他/定位符缺失 | 显示明确原因 | 不退化到任意软件、工作目录或第一个窗口 |

桌面客户端会话链接明确指定目标应用；系统接受链接的结果命名为 `conversationRequested`，不声称该回调本身能证明客户端已经渲染目标聊天。实际终端宿主优先于 Agent 名称；旧 `ts:<ID>` 不能精确解析时报告缺少标识，不能改跳 Codex 桌面。

子任务先解析父会话，并使用父会话整套 ID/终端元数据。循环引用、父会话已不存在时明确失败。桥接增加 WezTerm/kitty pane ID 和 TTY 采集；检测到 tmux 时保留其内层来源，当前没有完整服务器/pane 精确协议就不错误激活外层 iTerm 会话。

终端操作有 5 秒截止时间，不把进程启动当作执行成功。命令使用受控 PATH，不将会话值拼接进 shell；AppleScript 参数作为字符串转义，并区分自动化权限拒绝、未匹配和执行失败。

### 界面反馈与未查看状态

- 会话列表、详情、Agent Flow、待处理请求的所有跳转入口共享结果处理。
- 跳转失败显示原因，不因点击动作直接收起或清除“完成未查看”。
- 精确请求被接受后才执行主动跳转的查看确认和收起回调；客户端原生链接仍可能在自身界面报告已删除的聊天。
- 排队期间开始并完成新一轮时，旧跳转不能确认新的完成结果；重复回调与已取消视图的迟到回调被忽略。
- 打开详情本身仍按原约定视为已查看。

### 自动收起

- 删除相互竞争的两个异步延迟回调，所有自动收起由鼠标采样与一个连续离开倒计时决定。
- 命中区覆盖实际窗口中的面板、岛和屏幕顶部；在区域内静止不计时。
- 离开时才开始计时；重新进入立即清空，下一次离开重新完整计时。
- 隐藏、重开、拖动、交互保护、设置变化等均重置旧计时。
- 保留原有三项设置：任务完成收起、展开面板移出收起、悬停展开/无会话移出收起，采用当前适用的最短正延时；0 只禁用对应规则。
- 已更新设置文案，明确所有倒计时都以鼠标离开为前提，原有偏好无需迁移。

## 验证结果

| 验证层 | 结果 |
| --- | --- |
| 完整 XCTest | 1619 项：1602 通过、17 条件跳过、0 失败 |
| 最终定向回归 | 91 项：90 通过、1 个既有时间采样测量条件跳过、0 失败 |
| 最终 Release 构建 | 通过；临时鼠标诊断代码已移除 |
| 原生缺失身份界面 | 点击无效会话卡片后显示具体原因，面板未因跳转失败立即收起 |
| 物理鼠标悬停 | 用户确认“符合预期”：面板内至少 5 秒保持展开，离开面板和岛后约 3 秒收起 |
| 桌面客户端协议 | 已核对本机 Codex、Cursor、WorkBuddy 原生处理代码，见协议核验文档 |

回归覆盖：同目录不同聊天、无效/伪造 ID、路径与查询编码、CLI 宿主优先、旧 Terminal 标识、父子会话、异步回调重入和新完成记录保护、终端命令非零/超时、重入取消与再次离开、配置改变和窗口可见性。

自动化工具的虚拟点击位置不等于系统鼠标实际位置。隔离诊断记录曾显示点击截图在面板内，但 `NSEvent.mouseLocation` 为 `(286.55,425.61)`，不在窗口 `{{558,640},{396,348}}` 中，因此程序正常按离开处理；此自动结果没有冒充悬停验收。随后物理鼠标由用户完成验证。临时诊断代码已从生产源码移除。

## 未验收与限制

- 原生控制工具以安全限制拒绝读取或操作 `com.openai.codex`。未绕过限制，因此不能把 Codex 页面的实际切换标为自动实机通过。
- Cursor、WorkBuddy 与各终端的真实多会话切换尚未逐个运行验收；当前是原生协议核验、路由/脚本/执行器测试通过。
- 无已验证精确协议的客户端、过期旧记录、缺失 TTY/pane 标识和 tmux 会提示无法定位；这不代表所有适配软件已获得精确聊天导航能力。
- 多屏和系统睡眠唤醒未在本轮实测。静止指针使用 0.2 秒采样，收起时刻存在采样和主线程调度误差。
- 完整测试日志中的只读存储错误属于已有故障注入用例，XCTest 失败数为 0；17 个条件跳过项目没有被记成通过。
