# 豆包工作（Doubao Work）连接器接入

更新日期：2026-11-25

豆包工作于 2026-08-25 公开发布，TRAE Work 与 Coze 并入其中。它没有公开的原生 hooks，可编程入口是「插件 → 新建自定义连接器」，支持 HTTP 与本地 STDIO 的 MCP。本项目的接入因此是**连接器级活动观察**，不是任务级 hook。

## 能力范围

- 可以显示：显式调用 `xisland_activity` 时上报的一句话活动、细节，以及连接器连接期间的会话状态。
- 不覆盖：完整任务生命周期、审批、问答、取消、工具入参与出参。
- 不能推断：连接器安静不等于任务完成；只有连接器断开（客户端退出或删除连接器）才视为本次观察会话结束。
- 只在「本地电脑」模式可用；云电脑模式无法执行本机命令。

## 准备工作

1. 确认 X Island 已安装，桥接程序位于 `~/.xisland/bin/di-bridge`。
2. 在设置页找到「豆包工作」，点击「查看接入文件」。X Island 会在自有目录准备：
   - `connector.json`：供核对的 STDIO 连接器定义；
   - `README.txt`：同样的步骤说明。
3. 准备文件不等于已接入；豆包工作不会自动加载它。

## 在豆包工作中添加连接器

1. 打开豆包工作客户端，切换到「本地电脑」模式。
2. 左侧进入「插件·技能·伙伴」→「插件」→ 右上角「+ 添加」→「新建自定义连接器」。
3. 服务器名称：`X Island`
4. 传输类型：`STDIO`
5. 命令：`<你的家目录>/.xisland/bin/di-bridge`
6. 参数：`doubao-work-mcp`
7. 保存并连接。

连接器启动的命令等价于：

```text
~/.xisland/bin/di-bridge doubao-work-mcp
```

它通过标准输入输出暴露一个工具 `xisland_activity`：

| 参数 | 必填 | 含义 |
| --- | --- | --- |
| `summary` | 是 | 一句话活动摘要，1–512 字节 |
| `detail` | 否 | 更长的细节，例如正在执行的命令或文件 |

调用后 X Island 会显示一条活动记录；工具会明确返回“只是活动上报，不代表审批或授权”。

## 让豆包工作主动上报

连接器只在被调用时才产生事件。可在任务开始时向豆包工作说明：

> 开始任务和每完成一个关键步骤时，调用 X Island 连接器的 `xisland_activity`，summary 写一句话进度。

这只是提示，不是强制协议；豆包工作可能忽略，也不会因此阻塞任务。

## 验证层级

| 检查 | 结果 |
| --- | --- |
| 连接器定义与路径校验 | 已测（拒绝相对路径与控制字符） |
| MCP 初始化、`tools/list`、`tools/call` 契约 | 已测 |
| 活动消息进入 X Island | 合成事件通过隔离 socket 验证 |
| 豆包工作真实客户端加载与调用 | **未验证**：需要在本机客户端手动添加连接器后实测 |

真实客户端未验证前，不应把该入口描述为“已完整接入”。界面显示“等待活动”，直到收到第一条真实上报。

## 安全

- 不需要密码、API Key 或任何凭据；连接器命令只指向本机桥接程序。
- 豆包工作的审批和问答仍在豆包工作内完成，X Island 不写回任何决定。
- 若客户端要求审阅连接器命令，请先核对路径再启用。
