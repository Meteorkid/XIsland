# XIsland / XNook 切换失败与双岛不可见修复

日期：2026-10-22。状态：代码与构建验证通过，尚未提交、发布或替换本机应用。

## 预期行为

- 切换到未运行的目标时，按目标应用路径投递显示 URL，启动目标。
- 当前岛保持显示，确认目标岛实际在屏幕上后再隐藏当前岛。设置窗口、进程存在、URL 投递成功均不算显示确认。
- 打开失败、目标缺失或 8 秒仍未显示时保留／恢复当前岛；重复手势不重复启动。
- 显式重新显示会取消旧切换，旧 open、poll、timeout、hide 与全屏检查不能覆盖新的显示意图。

## 根因及修复

原实现依赖 URL scheme 的默认处理器，成功回调没有验证目标窗口；裸隐藏通知无条件 orderOut，启动决策只看进程。另有全屏异步结果迟到及旧保护计时器覆盖新切换的竞态。XNook 的鼠标屏幕显示入口还残留用户隐藏标记。

两端现在优先解析正式安装路径，并使用 NSWorkspace 定向打开目标。窗口确认检查目标 bundle、路径、PID、on-screen、alpha、尺寸和岛窗口层级；保留 XIsland statusBar+1 与 XNook statusBar+2。新隐藏通知附来源及显示时间，拒绝比本地显式显示更旧的消息；旧版裸通知在 pending 时要求目标可见，其余情况下要求目标岛置顶。完整迟到通知保护需要两端升级。

切换请求有独立 ID、取消及超时；启动前收到的显示 URL 暂存到窗口初始化后处理。初始显示仲裁依据目标窗口可见性。窗口显示、切换标志及后续全屏检查会淘汰旧检测结果。两端延迟清除保护时均确认没有新出站切换。
