# 双岛左右跟手切换

用户于 2026-10-25 选择“跟手滑动，松手切换”。两端以 XIsland 2.0.11 / XNook 1.3.22 已发布源码为基线实现，保留当前数据、审批和组件功能。

## 交互

- 仅在鼠标下最上层的收起岛响应横向精确手势；展开面板的横向内容交互继续原样处理。
- 开始后累计少量距离再锁定横轴；输入沿用 AppKit 根据自然滚动设置处理的方向。
- 横滑过程中只预览当前岛内容层，保留窗口命中区域；约束最大位移并提供阻尼。
- 未达到灵敏度阈值、反向滑回或取消时回位；超过阈值后仍等待松手才启动目标应用。
- 已提交手势的惯性尾部不能触发反向切换或下滑展开；目标可接收下一次新的 began，不再固定锁死 0.8 秒。

## 双端过渡

- 两端统一为 0.28 秒方向滑动，源沿输入方向退出，目标从反方向进入；使用 Core Animation 插值，不以少量手工 alpha 帧模拟平滑。
- 方向、事务 UUID、减弱动态标记和系统 uptime 通过提交时的可选 /show 参数传递。
- 目标先原子收起并提交最终布局，再显示窗口、发送同事务回执和共同动画开始时间；只有回执匹配且窗口服务器确认目标岛可见后，来源才让位。
- 如果回执先于 CG 可见性到达，先缓存回执，再等待可见确认；旧回执不能影响新请求。
- 旧版同伴忽略新增 query 仍可显示；新端在可见后短暂等待回执，缺少新回执则退回普通淡出，不伪造新协议成功。
- 8 秒超时或目标启动失败时，来源保持/恢复可用；预览不足阈值不启动对端。
- 任何一端请求减少动态效果都禁用方向运动；本地偏好和系统设置不能被远端覆盖。
- 显式显示、隐藏、展开、窗口关闭和审批接管会废止旧动画；快速反向从当前 presentation 位置接续。

## 验证与交付

覆盖手势序列、惯性、横纵轴、方向编码、坏参数、重复/过期回执、冷启动、可见性确认、超时恢复、减少动态效果、旧版本兼容和审批草稿。同步比较两端协议/Animator/识别器源文件，分别运行完整测试及 Release 构建。

静态渲染或模拟时钟不代表真实刷新率与触控板手感。两端不同刷新率、自然滚动开关、快速反向和冷启动的最终手感需要候选 App 的实机验收。用户随后明确批准备份并安装候选版。首轮候选已安装，能双向切换，但用户反馈两岛大小不同使交接割裂；此反馈尚不构成手感验收。当前继续修复并更新候选，不提交、推送或发布。


## 尺寸连续性修订（2026-10-25）

用户将“帧率不够高”进一步定位为两端轮廓尺寸不同，并非已测量到刷新率下降。因此本轮针对交接几何修复，不以提高定时器频率替代问题定位。

- 原先整个背景与内容一起移动，且两端各按自己的宽度滑动。新实现保留共同外壳，只平移前景，文字和图标不缩放。
- 可选几何扩展携带实际可见背景的屏幕坐标、显示器编号、宽高、圆角和填色；排除两端 6/4pt 的屏幕外延伸和透明窗口边距。
- 目标回执补全目标几何，来源校验其携带的源几何与本事务一致。两端沿统一时间和统一距离过渡。
- 独立、不可交互的临时原生窗口承载两种轮廓的并集，层级低于两端前景；Core Animation 同步插值路径和填色。前景由静止容器遮罩裁剪，结束/取消恢复背景并关闭临时窗口。
- 拖动预览时外壳保持原位，短滑松手后内容回弹；切换失败仍恢复来源。
- 几何缺失、旧版、跨屏或 XNook 玻璃材质使用兼容过渡。玻璃保留原材质，不替换成不透明假玻璃。远端坐标必须在实际屏幕内才启用形变。
- 入站/出站阶段的窗口尺寸请求合并，完成后刷新；目标准备阶段仍允许原子收起。问答草稿与原有悬停规则继续保留。

验证包含几何协议、宽高双向变化、负屏幕坐标、背景真实边界、前景不缩放、环境传递、像素渲染、取消恢复以及原有交接测试。离屏渲染和动画参数检查只能证明这些结构条件，不能代替真实双指手感或屏幕实际 FPS 验收。

## 松手后旧岛闪回修复（2026-10-25 晚）

用户实测上一轮候选后明确反馈“松手切换后，旧岛又闪回来”，故上一轮视觉验收失败，不能以此前自动测试通过代替用户验收。

### 已复现及修复

1. 已提交手势在等待回执时仍保留预览标记；遮挡/失采路径会执行普通取消，把源岛恢复原位。两端现在在 isSwitchingApps 期间保留已提交姿态；真正取消事务先清切换标记，再允许回弹。
2. XIsland 的隐藏、两端关闭以及 XNook 的显式隐藏曾在原生窗口隐藏前恢复视觉。现在先失效代数和待处理回调，原生窗口隐藏后才恢复背景、透明度与姿态。
3. XNook 直接 orderOut 还会留下待完成的入站代数；现在显式隐藏同步使其失效，迟到准备回调不能重新显示。
4. 设置中的“立即切换测试”使用定向动画入口，从而覆盖新几何交接，不再只测试兼容淡入淡出。

XNook 行为回归先确认红灯（3 项共 8 个断言失败；另显式隐藏入口 1 项 2 个断言失败），修复后同组全部通过。XIsland 本轮 45 项交接/外壳检查及 77 项窗口/手势/路由检查通过；XNook 使用 XNOOK_RENDER_UI=1 补全 151 项相关检查，零跳过、零失败。本轮共 273 项相关回归通过，未把上一轮全量回归数字当作本次重跑结果。

对 SwiftUI 重绘覆盖动画的猜测单独做了 6 次 rootView 更新采样，未复现图层复位；测试窗口保持隐藏，因此仅记为离屏取证结果。本轮保持现有动画架构，针对上述已复现的时序修复。关于 layer-backed NSView 的动画边界参考 [Apple Core Animation 文档](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/CoreAnimation_guide/CreatingBasicAnimations/CreatingBasicAnimations.html)。

## 果冻动画插值回归（2026-10-25）

用户确认旧岛不再闪回后，反馈鼠标移入弹动以及展开/收起都不顺滑。本轮保留原有弹簧参数、倍率、采样周期及已经验收的窗口隐藏时序，修复背景分层引入的插值边界。

### 定位与最终实现

- 原嵌套 NSHostingView 每次 rootView 赋值没有携带父图的动画插值。鼠标弹动的 6 次离屏样本直接停在245×76pt，纯SwiftUI则从261×61逐步变化并过冲；静态端点图片一致，未复现裁剪。
- 展开宽高本来连续，但内层圆角首帧跳到目标值。只将scale外移不足以同时修复展开/收起。
- 完整透传父Transaction虽恢复圆角，却让内层尺寸重复执行弹簧；该实验版本未安装。给NSViewRepresentable直接加Animatable也未驱动中间值。
- 最终以普通SwiftUI View + Animatable统一插值上下圆角、阴影透明度/半径/纵向偏移与描边透明度；内部原生renderer只画当帧（animation=nil、disablesAnimations=true），宽高与hover缩放保留原外层SwiftUI动画。
- 实际背景绘制及对端几何都使用同一组当前样式值；没有改窗口隐藏顺序或松手后预览保护。

### 验证

- 最终生产wrapper的离屏联合复测：实际轮廓与同帧native frame最大差宽0.618pt/高0.239pt（像素边缘量化级）；圆角进度同步，未再出现前一实验的大幅滞后或额外过冲。Hover也有连续中间态与回弹。
