# A 类功能实现说明（2026-11-04）

范围：系统通知（A1）、推送与 Webhook（A3）、不打扰策略（A4）、会话生命周期（A5）、脱敏诊断导出（A6）、会话感知防休眠（A7）。B 类见 `docs/plans/future-backlog-paid.md`。

> **范围变更（2026-11-04）**：A2 全局热键已按用户决定移除。`GlobalHotKeyManager.swift`、`HotKey.swift`、设置项、快捷键注册、文案与 3 个测试用例一并删除，不保留死代码。下文涉及热键的历史记录仅作过程留档，不再代表当前实现。

## 架构决策

所有 A 类消费者共用**一条事件流**：`SessionManager.publishToCompanion()` 已经是「新消息 / 关闭 / 超时淘汰」三条会话变更路径的唯一出口，因此在该方法里加一次 `ASuiteEventRouter.shared.sessionsDidChange(sessions)`，而不是往 SessionManager 里散落第二套通知调用。`ASuiteEventRouter` 负责把 `[AgentSession]` 转成纯值 `IslandSessionSummary`，推导 `IslandEvent`，再分发给通知、推送、生命周期与防休眠。

**纯策略与系统层分离**是本轮的核心约束：`Models/` 下的推导、`DoNotDisturbPolicy`、`SessionLifecyclePolicy`、`KeepAwakePolicy`、`PushChannelRequestBuilder`、`EventRedaction`、`HotKeyRegistry` 全部是纯函数/值类型，可在 XCTest 里用字面量断言；`Managers/` 下的 `SystemNotificationCenter`、`GlobalHotKeyManager`、`PushNotifier`、`SessionKeepAwakeController` 只在生产环境激活。四项系统 API 都有 `isAvailable` 门控（`!AppPreferences.isIsolated`），并有测试锁定该门控。

## 安全与默认行为

- **所有新开关默认关闭**。通知权限、全局热键、对外网络请求、防休眠断言都是系统级侵入，必须用户显式开启。
- 通知里的批准/拒绝按钮**默认不存在**；须显式开启 `asuite.notifications.allowDecisions`，回传时还要过三重校验：开关已开 + 通知带 requestID + 请求仍存在且 UUID 精确匹配。过期请求一律忽略，绝不隐式批准。
- 推送/Webhook 正文出本机前统一走 `EventRedaction`（凭据、Bearer、厂商密钥、长随机串、邮箱、URL 凭据、家目录、长度上限）；推送只发文本，**不代替审批**。
- 诊断包用白名单键，渠道地址、附加标识、授权信息与历史正文一律不进入；文本生成后再脱敏一次。

## 已知限制（诚实清单）

1. **系统通知需要 app bundle**：`UNUserNotificationCenter` 要求 `Bundle.main.bundleIdentifier` 非空，SwiftPM 裸可执行文件为 nil，此时 `SystemNotificationCenter.isAvailable` 返回 false 并静默跳过。发行时须由 `Scripts/package-dmg.sh` 产出 `.app` 才能真正生效。这一点未做真机验证。
2. **全局热键、IOKit 断言、推送实际送达均未真机验证**：测试隔离环境刻意禁用全部系统 API，本轮验证只覆盖策略层与请求构造层。
3. **A5 跨重启身份关联只落地了策略函数** `SessionLifecyclePolicy.associate`，未接入 `SessionPersistenceManager` 的恢复路径。原因：改动持久化恢复有误并历史的风险，应与 B2「真实客户端完整验收」一并做，不在本轮单独接线。`autoHide`、`superseded`、`reap` 三项已接线并作用于显示层。
4. **进程存活用代理指标**：`AgentSession` 没有 pid 字段，A5 的失联判定使用 `observationEndedAt != nil` 且超过宽限期，不是真实的 `kill(pid, 0)` 检查。
5. **新增文案只有简中与英文**：既有 `L10n` 覆盖 5 语种，本轮约 60 条新文案在 `ASuiteL10n` 里，韩/日/法回退英文。未用机翻填充。
6. 推送无重试、无 in-flight 上限；配置不合法时静默跳过。已加 10 秒请求超时 / 20 秒资源超时，弱网下不会无限挂起。电池读取为 best effort，读取失败时不启用低电量暂停。

## 验收与审查修复记录（第二轮）

验收数据：`swift build` 0 错误；A 类专项 **49 项 0 失败**；全量 **1980 项、19 跳过、0 失败**（基线 1973 + 新增 7）。

独立审查发现 19 项问题，其中 15 项已修复，4 项记录为有意保留：

**已修复**

1. **首次启动就请求通知权限** —— 违背「默认关闭」。改为仅在用户开启通知时 `configure` / `requestAuthorization`。
2. **未授权时 A 类设置页不可达，且 lockdown 不停 router** —— 用户既关不掉热键/断言也看不到开关。设置页白名单加入 `.automation`；lockdown 首行 `router.stop()`；重新激活时 `configureASuite()` 恢复，并重置设置签名以便重新注册热键。
3. **待查看的完成会话被自动隐藏** —— `shouldAutoHide` 增加 `needsReview` 参数，未查看的完成永不隐藏。
4. **等待态但无交互请求的会话被同工作区取代** —— superseded 规则同时排除 `waitingPermission/waitingAnswer/waitingPlanReview`，避免卡片彻底消失。
5. **防休眠断言在宽限期后不释放** —— 增加 `keepAwakeReevaluation` 定时重算；否则最后一个会话结束后断言永久持有。
6. **多条跟进提醒互相取消** —— `followUpWork` 由单槽改为按 sessionId 的字典。
7. **错误/完成事件判重错误** —— 改为请求型事件用 `emitted` 跨轮去重、状态型事件按上一轮状态迁移判定；修复「同一错误反复提醒」与「恢复后二次出错不再提醒」。
8. **推送硬编码抑制子会话** —— 改由 `DoNotDisturbPolicy.suppressSubagents` 决定，与设置开关一致。
9. **推送标题未脱敏** —— 标题会进入 Bark URL 与所有渠道正文，`PushRequestBuilder` 统一脱敏。
10. **深路径未裁剪** —— `redact(path:)` 在替换家目录后，超过 4 段只保留末两级。
11. **声音静默与设置页键名不一致（既有缺陷）** —— `AudioEngine` 读 `audio.quietHours*`，设置页写无前缀键，用户配置从未生效；已统一为无前缀键并修测试。
12. **`UserDefaults` 观察者 token 未保存** —— 保存并在 `applicationWillTerminate` 移除。
13. **reap 同步重入导致外层用过期快照** —— `onReapSessionIDs` 延后到下一轮主线程执行。
14. **设置签名漏通知开关、模式切换不立即评估** —— 签名补入 `notificationsEnabled`；`applySettings` 末尾立即评估一次防休眠。
15. **推送无超时** —— 改用 ephemeral URLSession，10 秒请求 / 20 秒资源超时。

**有意保留（非缺陷）**

- 静默时段起止相同视为「未配置」而非全天静默：宁可多提醒，也不要把用户静默一整天。代码注释已说明。
- `IslandEventKind.backgroundCompaction` 当前无生产者，保留为策略层第二道防御闸。
- Swift 6 严格并发下 `PushNotifier.sendTest` 的 completion 与 router 的观察者闭包仍是迁移点；当前 Swift 5 模式编译通过，迁移时改为 `Task { @MainActor in }`。
- `SessionLifecyclePolicy.associate` 仍只做策略层，未接持久化恢复（见已知限制 3）。

## 发行级验收（第三轮）

| 项目 | 结果 |
|---|---|
| `swift build -c release` | 通过，69.6 秒，0 错误 |
| 按生产模板组装 `.app` | `plutil -lint` OK；`CFBundleIdentifier = dev.xisland.app`；ad-hoc 签名有效 |
| 隔离模式启动（`--ui-test-mode --open-preferences`） | 存活 6 秒无崩溃，stderr 为空 |
| 测试隔离 | 使用独立 UserDefaults suite，未写入真实偏好 |

**本轮发现的发行缺陷**：`Scripts/build.sh` 的 Info.plist 模板缺少 `NSLocalNetworkUsageDescription` 与 `NSBonjourServices`。伴端使用 MultipeerConnectivity（服务类型 `xisland-buddy`），macOS 缺少本地网络用途说明时无法正确发起权限请求，表现为「手机永远发现不了 Mac」。已补入 `_xisland-buddy._tcp` / `_udp` 两条 Bonjour 声明。

**验收未覆盖**：临时 bundle 不含 `SoftwareLicensePublicKey`，启动后处于未授权状态，无法开启 A 类功能做交互验证。通知回执、全局热键、IOKit 断言三项仍需在带真实授权公钥的发行包上手工确认。

**本轮同时修掉的授权绕过**：第二轮把 `.automation` 加入未授权白名单，虽然解决了「关不掉」，但未授权用户也能直接开启系统通知、热键与防休眠。现改为页面可达但整体 `.disabled`：只读展示 + 提示需要授权；已开启的项在授权过期时由 lockdown 停止。这样既能让用户看到并理解这些能力，也不构成绕过入口。
