# 任务提醒与优先回到 XIsland

## 行为约定

用户要求新增功能按钮：任务完成后回到 XIsland，吉祥物跳跃提醒查看；审批或提问到达时回到 XIsland 并自动展开。

- 常规设置和展开面板铃铛按钮共用“任务提醒”开关，默认开启。关闭后不自动争取双岛显示权、不播放新增跳跃；用户仍可手动查看和处理请求。
- 真实任务完成才提醒，重复结束、历史恢复/重放、失联和完成未确认不当作新完成。打开详情或主动跳转才沿用现有“已查看”确认。
- 同一批多个事件合并显示，审批/提问优先。真实请求展开对应交互；仅观察到等待状态的客户端展开总览，不伪造审批能力。
- 提醒先安全显示 XIsland，再通知另一款岛让位。旧的切换请求/异步准备不能覆盖更新的提醒；之后用户主动切换仍允许。
- 吉祥物整体短暂双跳和轻摆，保留原颜色/状态角标，不增加无限动画计时器；遵循减少动态、禁用动画选项。未查看任务优先进入最近任务图标候选，仍遵守数量上限及已有历史保留策略。
- 自动提醒不自动审批、回答、不改客户端信任，不主动打开会话详情，不切走当前编辑应用的键盘焦点。

## 实现与验证

以 SessionManager 的真实状态转换发出带完成时间/请求身份的事件，由单独的展示协调器合并并在展示前复核。AppDelegate 使用现有窗口显示及双岛隐藏协议，NotchContentView 负责安全展开，AgentIcon 负责有限头像动画。

验证覆盖完成去重和下一轮、历史重放、请求替换、关闭开关、审批优先、过时切换、准备完成回调、最近任务排序及减少动态。另做完整 Swift 回归和两端构建；真实双指和当前前台抢占体验须独立验收，不能由单元测试代替。

## 已完成实现

- 展开面板新增铃铛按钮，右键菜单和设置同步同一开关；关闭后立即停止新增跳跃和自动切回，切回不会抢走编辑应用的键盘焦点。
- 每个会话记录提醒代次。已查看、已回答、被替换及重新开始的请求在实际展示前再次校验；80ms 内事件合并，交互优先，重复原生请求不会重复切回。
- 完成只显示岛和头像提醒，不打开详情、不标为已查看。纯观察接入的等待状态展开总览，保留跳回客户端处理的能力边界。
- 原有“只因 XNook 进程存在，审批结束就自动返回 XNook”的逻辑已移除，避免处理完立即被切走。之后用户主动切换仍然可用。
- 跳跃只在岛可见时播放，约1.05秒两次小跳和轻摆，停止后仍保留状态角标。关闭或减少动态时不播放；隐藏不会消耗可见提醒动画。
- 提醒优先于全屏自动隐藏；查看/处理或关闭提醒后恢复原偏好。完成提醒定位活动屏但不遗留跨屏锚定，审批/提问继续保持原有展开期间锚定。
- 两端新增跨进程 epoch：提醒作废旧 URL、准备回调及发送方超时/轮询，避免旧岛随后夺回显示权。旧版完全不带时间/epoch的普通 `/show` 仍保留兼容，其入站后的准备回调受保护；新候选所有切换 URL 都有 epoch。
