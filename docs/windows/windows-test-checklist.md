# Windows 预览版验收

版本：0.1.7 开发预览。安装包从源码交叉构建；以下运行检查尚未在 Windows 完成。请在另一台测试电脑逐项记录结果，失败时保留截图与具体步骤。

## 安装和环境

1. 记录 Windows 版本、x64/ARM64、显示器数量和每块屏幕缩放比例。
2. 核对安装包 SHA-256 与同目录 manifest 一致，再安装。记录是否需要下载 WebView2、安装目录和所有系统提示。
3. 启动后确认顶部浮岛、托盘图标及单实例行为。运行 `Test-XIsland.ps1` 获取只读报告；脚本不会创建审批或修改 Agent 配置。

## 外观与输入

- 收起/展开：默认收起主条 261.34×38.77 DIP，活动文字增加 22 DIP；普通展开宽 380 DIP。检查顶部平直、底部圆角、文字可读、阴影和颜色。
- 独立设置：打开后灵动岛不变成大面板；关闭设置不退出应用。主题、五语言、动画、勿扰设置重启后仍在。
- 输入：中文输入法组合输入时接收新事件、切换会话或等待几秒，候选文字不能丢失；单选、多选、自定义回答和计划反馈分别操作。
- 窗口：悬停或收到任务不抢走终端正在输入的焦点；显式点击输入框能正常输入。拖动只改变顶部水平位置，不误触展开。
- 显示器：100%、150%、200% 缩放，跨屏移动鼠标、负坐标副屏、拔掉副屏；审批出现后不会被鼠标移动拉走。全屏隐藏默认关闭，启用后只在相应屏幕生效。

## 首批 Agent 接入

每种工具单独记录产品版本和运行方式（原生 PowerShell/Windows Terminal/IDE/WSL）；不要把一个工具通过推广为其他工具通过。当前首批安装界面面向原生 Windows，WSL 不作为已经实现的兼容结论。

1. 用独立临时项目，启动后检查“软件接入与授权”的自动准备结果；也可先关闭对应自动开关，再查看计划手动操作。确认原有其他 hook 和设置仍存在、备份文件已生成。
2. 新建任务，检查开始、工具调用、完成/等待状态与原客户端一致。
3. 对有已实现交互的客户端触发只读文件或安全测试命令审批，分别选择允许/拒绝；核对原客户端接收到正确结果。
4. 同时开两个会话，交替发起请求，确认不会串会话；重复点击不重复响应。
5. 等待期间关闭原客户端或退出 XIsland，重新打开后旧请求不能被再次批准。
6. 在配置已被其他程序修改后确认旧安装计划，应该报告冲突并要求重新查看，不能覆盖新配置。

能力边界：Gemini 首批仅观察；Claude 多题/原生多选仍由原客户端处理；Cursor 不同 hook 有各自的阻断和失败策略。界面出现配置成功不能替代以上真实任务步骤。

### 新增五种 Agent 与自动接入

1. Agents 页应有 11 个配置入口及 WorkBuddy 插件导出。分别记录“检测到客户端”“已配置”“当前配置最近收到事件”；只装配置、没有原生事件时不能报告连接已验证。
2. Codex：保留原客户端的信任步骤。未信任时应显示待授权；信任撤销或配置更新后不应继续显示旧事件作为当前连接证据。
3. Qwen Code：独立测试 PermissionRequest 的允许与拒绝，确认原端实际执行/拒绝。子代理停止不能结束父会话；普通问答仍在原客户端完成。
4. OpenCode：确认自动加载 `xisland.js`；分别测试权限允许/拒绝、单选、多选及连续多题。完整多题结果应一次回到同一请求；中途取消、客户端原端回答、删除会话后不能残留可点击旧请求，也不能把删除显示为成功完成。
5. CodeBuddy Code CLI：确认 Git Bash 可用，检查观察事件与工具 ID；不要用 WorkBuddy 代替此项。Droid：同时有 settings 和独立 hooks 文件时，应更新既有生效文件；查看计划后更改所选文件应触发冲突保护。
6. Kimi：记录 npm 包名和版本，只测试 `@moonshot-ai/kimi-code` Node 版。触发后台进程/子代理的成功、失败和取消；核对任务身份、父会话、历史重启及失联问号。Python `kimi-cli` 不应被当作已检测到兼容客户端。
7. 观察模式（CodeBuddy、Droid、Kimi）不出现代替原生授权的按钮；关闭 XIsland 后原客户端继续运行。升级/移动 XIsland 后刷新接入计划，旧资源回执应失效；手工改过的 OpenCode 插件或 Kimi TOML 块必须报告冲突，不能覆盖用户改动。

### TraeWork CN / WorkBuddy 专项

1. 记录产品完整名称、版本和本地/云端任务类型。当前只验收 Windows 本地任务。
2. TraeWork CN：使用“TRAE CN / TraeWork CN”共享入口，在原客户端确认 hooks 已启用/受信任。检查开始、工具结果、等待确认和回复状态；同时打开 IDE 时只应有一套共享命令。分别触发 IDE 与 Work 的本地事件，检查来源标签是否正确；识别失败允许保留共享标签，不能误标成另一款产品。
3. WorkBuddy：从 Agents 页导出插件，在 WorkBuddy 添加本地市场后安装启用；回传本地市场是否可加载、11 个 hooks 是否实际触发。导出目录本身不是安装证明。
4. WorkBuddy 子代理结束不能使父任务显示完成；Stop 后若客户端继续工作，浮岛不能抢先宣布成功；FinalStop 的已知原因才更新空闲/错误。
5. 等待授权时回原客户端完成操作；XIsland 不显示可替代原生审批的按钮。关闭 XIsland 后 WorkBuddy 应继续原生流程，不能因观察 hook 被卡住。分别测试冷启动及运行中断；已有旧插件须先移除后重新导入本次导出版本 0.1.1。
6. 移除接入分别验证：TRAE 共享入口移除影响两款产品；WorkBuddy 需在原客户端停用/卸载插件，再移除市场。卸载 XIsland 前完成这些操作。

## 数据与发行

### 0.1.7 跟进 Mac 更新专项

- 首次启动：未安装的软件不应写配置；已安装且自动开关开启的来源准备一次。开关关闭后周期检查不补回，手动移除后也不恢复。重新打开设置/重启时，同一配置不重复提醒。
- 关闭与交互：检查中关闭设置，结果返回后不再次弹出；有真实待答请求时接入提醒延后，处理完后仍能查看。
- Codex：撤销信任后旧“已接入”消失；重新信任但没有新事件时保持等待活动，实际新任务接纳后再接通。
- 文件准备：WorkBuddy/Kiro 相同产物复用；修改准备目录内文件后不被覆盖。点击“打开接入文件夹”定位正确目录。Kiro 只测试 Windows 11 原生 CLI 2.31.0 V3 对应路线，按 README 放置后确认 `/config` 来源，再验证六类事件。无答案 Stop 保持未确认状态，不能显示虚构助手回复。
- 数据与声音：同一原生任务多个观察实例不重复累加累计 tokens/费用；历史按结束/中断时间排序，模型名可见且长名称不撑破布局。最终回复到达 idle 时音效响一次，流式片段、重放、旧消息修正、副窗口与勿扰不重复响。

- 完成任务后重启，历史和统计还在，但没有新事件的旧任务不应伪装为仍在运行。
- 导出 JSON 并检查可读；删除一条已结束历史后重启，记录不会复活。
- 升级安装保留设置与历史；卸载记录实际删除范围。若准备卸载，先从 Agents 页移除本应用接入，避免留下指向已删除程序的命令。
- 安装包当前未签名；系统阻止时记录提示，不修改全局安全策略。
