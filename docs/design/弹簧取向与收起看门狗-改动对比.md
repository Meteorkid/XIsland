# 弹簧取向调整 + 收起看门狗 — 改动对比

承接《竞品UI设计借鉴-Sapphire与TODO-Panel》调研中的第 ①② 条建议。
来源：Sapphire（`cshariq/Sapphire`，AGPL-3.0）。**仅借鉴思路，未复制代码。**

验证：`swift build` 通过，`swift test` **1495 通过 / 0 失败**（新增 10 项）。

---

## ① 弹簧参数：取向修正

### 改了什么

`Sources/DynamicIsland/Models/IslandMotionTokens.swift`

| 档位 | 方向 | 改前 response / damping | 改后 | 变化 |
|---|---|---|---|---|
| low | 展开 | 0.28 / 0.92 | 0.28 / 0.92 | — |
| low | 收起 | 0.24 / 0.90 | 0.24 / **0.95** | 更接近临界 |
| **medium** | **展开** | **0.4 / 0.82** | **0.4 / 0.55** | **阻尼大幅降低，出现明显回弹** |
| **medium** | **收起** | **0.35 / 0.80** | **0.30 / 0.98** | **更快、几乎不过冲** |
| high | 展开 | 0.5 / 0.74 | 0.5 / **0.45** | 回弹更强 |
| high | 收起 | 0.44 / 0.72 | 0.34 / **0.98** | 更快、不过冲 |

### 为什么改

**原取向是反的。** 展开阻尼 0.82 接近临界，位移曲线近似线性，观感生硬——但展开恰恰是
「面板从刘海长出来」的过程，需要一次可见回弹才有生命感。而收起阻尼 0.80 低于临界，
会产生可见的尾部过冲，可收起是「消失」，尾部抖动显得廉价。

Sapphire 的取值方向相反且一致：`expand = 0.4 / 0.55`（弹），`collapse = 0.3 / 0.98`（利落）。
这不是风格差异，而是**两个动作的语义不同**：展开是「生长」，收起是「消失」。

### 你会看到什么

- **展开时**：面板边缘会轻微越过目标尺寸再回弹落定。medium 档阻尼从 0.82 降到 0.55，
  回弹幅度从几乎不可见变为清晰可感。
- **收起时**：此前收尾可能有一两帧的过冲抖动，现在干脆落定。
- **low 档**：基本不变（0.90 → 0.95 的收紧只在尾部，肉眼难辨），仍是「克制」选项。
- **high 档**：展开回弹比 medium 更明显。

### 结构调整（无行为影响）

原来 `expandSpring` / `collapseSpring` 各自 `switch` 硬编码。现在改为**数据表驱动**：

```swift
struct Spring: Equatable {
    var response: Double
    var dampingFraction: Double
    var animation: Animation { .spring(response: response, dampingFraction: dampingFraction) }
}

static func spring(for intensity: IslandAnimationIntensity) -> (expand: Spring, collapse: Spring)
```

**原因**：`Animation` 不暴露 `response` / `dampingFraction`，而看门狗需要按弹簧参数反推超时。
先存参数、按需构造 `Animation`，可保证同一组数值只写一遍——否则「改参数忘了改超时推算」是必然的。

`expandSpring` / `collapseSpring` 改为查表转发，**所有调用点无需改动**。

## ② 收起看门狗：健壮性兜底

### 要防的真实故障

`NotchContentView.swift` 的 `collapse()` 里，`collapseAnimating` 只由 `finishCollapse` 复位，
而 `finishCollapse` 带一道守卫：

```swift
guard generation == self.collapseGeneration, self.state == .collapsed else { return }
```

若这道守卫不成立（收起过程中状态被改写），或该回调因窗口重建、runloop 被占满而丢失，
`collapseAnimating` 会**永久保持为真**。后果是连锁的：

```swift
private func reportSize() {
    guard !collapseAnimating else { return }   // ← 首行即返回
    onSizeChange?(contentWidth, contentHeight, true)
}
```

**面板尺寸从此不再上报**，窗口停留在一个错误的尺寸上，表现为「卡住、无法交互」。
用户侧无法自愈，只能重启应用。

### 改了什么

`Sources/DynamicIsland/Views/NotchContentView.swift`

1. 新增 `@State collapseWatchdogWorkItem`
2. 新增 `scheduleCollapseWatchdog(generation:normalCompletionDelay:)` / `cancelCollapseWatchdog()`
3. `collapse()` 末尾调用看门狗
4. 三处取消点：`finishCollapse` 成功路径、`expand()` 开头、`onDisappear`

**超时值由参数推导，不是硬编码**：

```
超时 = collapseCompletionDelay + settleDuration(for: intensity)
```

| 档位 | collapseCompletionDelay | settleDuration | 合计兜底 |
|---|---|---|---|
| low | 0.28 | 0.24 × 1.6 = 0.384 | 0.66s |
| medium | 0.45 | 0.30 × 1.6 = 0.480 | 0.93s |
| high | 0.55 | 0.34 × 1.6 = 0.544 | 1.09s |

`settleDuration` = `collapse.response × overshootFactor`，系数取 `damping < 0.8 ? 2.4 : 1.6`
——低阻尼的尾部震荡更长，需要更大余量。这与 Sapphire 用 `visualSettleFraction` 提前收敛
是同一考虑（对方要精确到帧，这里只需一个安全上界）。

### 介入条件是严格的

判定抽成静态函数以便单测：

```swift
static func shouldWatchdogForceSettle(
    watchdogGeneration: Int, currentGeneration: Int, collapseAnimating: Bool
) -> Bool {
    watchdogGeneration == currentGeneration && collapseAnimating
}
```

**世代检查是关键**：若期间发生过新的收起或展开，`collapseGeneration` 已递增，
旧看门狗必须退出——否则它会去「收拾」一个已经不属于它的动画，把窗口尺寸改错。
正常路径会先复位 `collapseAnimating` 并取消看门狗，因此不会与兜底重复介入。

### 你会看到什么

**正常情况下完全看不到差别**——这是一条不会触发的保险。只有在原本会「卡住」的场景下，
面板会在约 1 秒内自动恢复，而不是永久卡死。

## 顺带清理：两个死令牌

`IslandMotionTokens.swift` 中删除：

- `Duration.statusSweepHold = 0.6` —— `StatusChangeSweep` 只有扫光动画、**没有对应的 `Task.sleep`**，
  该令牌在 Sources 里零引用，却被测试断言着，等于在锁定一个不存在的行为
- `Duration.cascadeItem = 0.34` —— 级联实际使用 `cardLift` 弹簧，此常量从未被引用

删除后同步移除了断言 `statusSweepHold == 0.6` 的测试行（否则会变成「断言死令牌」的假测试）。

## 测试

新增 10 项（令牌 7 + 看门狗 3），全量 **1495 通过 / 0 失败**。

令牌侧锁定的是**取向不变量**，而非具体数值：

| 测试 | 锁定的性质 |
|---|---|
| `testExpandSpringIsMonotonicInIntensity` | 强度越高，周期越长、阻尼越低 |
| `testCollapseSpringResponseIsMonotonicInIntensity` | 收起周期随强度单调递增 |
| `testDefaultAndHighExpandAreBouncy` | medium / high 展开阻尼 < 0.8 |
| `testCollapseIsCriticallyDampedInAllIntensities` | **所有档位**收起阻尼 ≥ 0.9 |
| `testExpandIsBouncierThanCollapseWithinEachIntensity` | **每档内展开阻尼 < 收起**——取向的量化形式 |
| `testExpandIsAlwaysSlowerThanCollapse` | 展开周期恒大于收起 |
| `testSettleDurationExceedsCollapseResponse` | 兜底时长必须长于动画本身 |
| `testSettleDurationIsBounded` | 兜底时长 < 2s（过长等于没有兜底） |
| `testSettleDurationUsesLargerFactorForLowDamping` | 系数随阻尼正确切换 |
| `shouldWatchdogForceSettle` 三项 | 正常介入 / 已收尾不介入 / 世代不符不介入 |

其中 `testExpandIsBouncierThanCollapseWithinEachIntensity` 是**本次改动真正的回归防线**：
若有人把两个取向又调反，它会立即失败。

### 一处自查修正

第一版断言 `testExpandIsBouncyAndCollapseIsCriticallyDamped` 要求**所有档位**展开阻尼 < 0.8，
测试失败（low 档是 0.92）。**是断言写错了，不是代码错了**——low 档本就是「克制」档，
不应参与回弹约束。已拆分为「medium/high 需回弹」与「全档收起需近临界」两条。

## 回退方式

两处改动都集中且独立：

- **①**：改 `IslandMotionTokens.spring(for:)` 表里的数值即可。要恢复原样：medium 展开改回 `0.4 / 0.82`，
  收起改回 `0.35 / 0.80`；high 展开 `0.5 / 0.74`，收起 `0.44 / 0.72`；low 收起 `0.24 / 0.90`。
- **②**：删除 `collapse()` 末尾的 `scheduleCollapseWatchdog(...)` 调用即完全失效，
  其余为新增代码，无副作用。也可只调超时系数。
