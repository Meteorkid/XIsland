## 1. 动效令牌层（纯重构，零视觉变更）

**新增文件**：`Sources/DynamicIsland/Models/IslandMotionTokens.swift`

### 原来是什么

动效参数**硬编码散落在各视图**，彼此无关联：

```swift
// NotchContentView.swift:253-284 —— 三档强度的 switch
case .low:    return .spring(response: 0.28, dampingFraction: 0.92)
case .medium: return .spring(response: 0.4,  dampingFraction: 0.82)
case .high:   return .spring(response: 0.5,  dampingFraction: 0.74)

// AnimationEffects.swift:79 —— 另一处，与上面无关联
withAnimation(.spring(response: 0.35, dampingFraction: 0.7))

// NotchContentView.swift:1139 —— 又一处
withAnimation(.spring(response: 0.5, dampingFraction: 0.3))
```

想统一调「所有卡片浮起的手感」，需要 grep 全项目找魔数。

### 现在是什么

所有参数集中在 `IslandMotionTokens`，按**用途**命名而非按数值：

```swift
IslandMotionTokens.expandSpring(for: intensity)   // 面板展开
IslandMotionTokens.hoverJellyPop                  // 悬停果冻（低阻尼，要明显回弹）
IslandMotionTokens.cardLift                       // 卡片浮起（中阻尼，不过冲）
IslandMotionTokens.hoverTransition                // 日常 hover（无过冲）
```

并补了一条 TO-DO Panel 的核心原则注释：**有回弹的曲线只给「有实体感」的元素；尺寸/位置变形用无过冲曲线**，因为过冲会让窗口边缘短暂露出裁切。

### 差异对比

| | 原来 | 现在 |
|---|---|---|
| 视觉表现 | — | **完全一致**（数值逐一对齐） |
| 调参成本 | 需 grep 全项目 | 改一处 |
| 新增动效 | 容易写出第 4 个不相关的魔数 | 有现成语义槽位 |

**这是本次唯一一项你无法在界面上看出区别的改动**——它的价值在维护性。我用测试锁定了重构前的数值：

```swift
// IslandMotionTokensTests.testTokenValuesMatchPreRefactorConstants
XCTAssertEqual(IslandMotionTokens.Duration.toolFlashHold, 0.5)  // 重构前 AnimationEffects.swift:29
```

若将来有人改动了这些值，测试会失败并提示「需确认是有意调参」。

### 如何回退 / 调节

纯重构，无需回退。若要调参，改 `IslandMotionTokens.swift` 一处即可全局生效。

## 2. 触觉反馈（本次最大增量）

**新增文件**：`Sources/DynamicIsland/Managers/IslandHapticEngine.swift`

### 原来是什么

**完全没有触觉反馈**。全项目搜索 `NSHapticFeedback` / `HTKMultitouch` 零命中。

用户在权限审批弹出时，只有视觉变化。

### 现在是什么

新增触觉反馈，按事件重要性分档：

| 事件 | 首次触发的档位 | 系统 pattern |
|---|---|---|
| 权限审批弹出 | 极简 | `.generic` |
| 操作失败 / 拒绝 | 极简 | `.generic` |
| 等待输入（问答/计划评审） | 标准 | `.generic` |
| 面板展开 / 收起 | 标准 | `.levelChange` |
| 会话切换 | 完整 | `.alignment` |
| 工具完成 | 完整 | `.alignment` |

### ⚠️ 必须说明的能力边界（这是我修正过的一处判断）

**macOS 公开 API 无法控制振动强度。** `NSHapticFeedbackManager` 只提供三种 pattern，没有幅度参数。

因此我这里的「强度」实际控制的是**事件覆盖范围**——档位越高，纳入反馈的事件越多。这与 Sapphire 的 `HapticFeedbackType`（真的能控制 `intensity: Float`）**不是同一件事**：

```swift
// Sapphire 的做法——私有 API，可精确控制幅度
HTKMultitouchActuator.shared().actuateActuationID(type.actuationID, intensity: type.intensity)

// 本项目的做法——公开 API，只能选 pattern
NSHapticFeedbackManager.defaultPerformer.perform(pattern, performanceTime: time)
```

**为什么不用 Sapphire 的方案**：`HTKMultitouch` 是未公开框架，调用它会导致**无法上架 Mac App Store**，且系统更新可能失效。我按报告中的建议选择了公开 API 版本。

如果你要精确的强度分级，需要接受上述代价——这是产品决策，需要你定。

### 差异对比

| | 原来 | 现在 |
|---|---|---|
| 权限审批 | 仅视觉 | 视觉 + 触控板轻震 |
| 展开/收起 | 仅视觉 | 视觉 + 触觉确认 |
| 覆盖范围 | 无 | 4 档可选（关闭/极简/标准/完整） |
| 上架风险 | — | 无（全公开 API） |
| 无触控板设备 | — | 静默无效果（系统自动忽略） |

**一个我特意处理的细节**：`.levelChange` 在部分机型上会附带一声听觉提示，因此我只把它用于**用户主动发起**的展开/收起，不用于被动通知——避免在用户没操作时突然发声。

### 如何回退 / 调节

- **完全关闭**：偏好设置 → 显示 → 触觉反馈 → 反馈强度 → **关闭**
- **只保留关键提示**：选**极简**（仅权限审批与失败）
- **默认值**：标准档
- **测试环境自动静默**：`AppPreferences.isIsolated` 为真时不触发，避免测试振动

## 3. 图标动效（macOS 14 可用子集）

**新增文件**：`Sources/DynamicIsland/Views/Components/IslandSymbolEffects.swift`

### 原来是什么

项目只在**一处**用了 SF Symbols 动效：

```swift
// NotchContentView.swift:1290 —— 活动日志的工具完成图标
.symbolEffect(.bounce, value: item.event.isComplete && ...)
```

`.pulse` / `.variableColor` 完全未使用。

### 现在是什么

抽出两个可复用修饰器，并接入真正的 SF Symbol 落点：

- **`ToolCompletionSymbolEffect`** —— 工具完成弹跳，行为与原来一致（保持兼容），但补上了 `isFailed` 判定与偏好开关
- **`AttentionPulseModifier`** —— 待处理任务卡片的跳转按钮持续脉动，表达「这里需要你」

### ⚠️ 一处我自查发现并修正的实现错误

**我最初把动效加错了位置。** 我第一版在 `AgentIcon` 外层加 `symbolEffect`，但核查后发现：

```swift
// AgentIcon.swift:54 —— size ≥ 20 时渲染的是自绘表情，不是 SF Symbol
if showMascot && size >= 20 {
    MascotView(status: status, size: size)   // 纯 Path 绘制 + 自带 TimelineView
} else {
    Image(systemName: agentType.iconSymbol)  // 只有这里才是 SF Symbol
}
```

`symbolEffect` 对 `MascotView` 的 Path 绘制**完全无效**，且 `AgentIcon` 内部已有自己的脉冲光环（`AgentIcon.swift:35-42`）。那两处接入是无效代码，我已撤除，改为接到真正的 `Image(systemName:)` 上。

**顺带说明**：`AgentIcon` 内部原本就有脉冲光环，所以「运行中的会话图标会呼吸」这个效果**一直存在**，本次没有新增。

### ⚠️ 部署目标限制（无法绕过的硬约束）

TO-DO Panel 的 `lucide-path-breathe`（图标被「重新画一遍」）对应的 `.drawOn` **需要 macOS 15**。本项目 `Package.swift:6` 是 `.macOS(.v14)`，因此该效果**当前不可用**：

| 效果 | 可用性 | 说明 |
|---|---|---|
| `.bounce` | macOS 14 ✓ | 已用 |
| `.pulse` | macOS 14 ✓ | 本次新增 |
| `.variableColor` | macOS 14 ✓ | 已封装但暂未接入 |
| `.drawOn` | **需 macOS 15** ✗ | 无法使用 |

### 差异对比

| | 原来 | 现在 |
|---|---|---|
| 工具完成弹跳 | 有 | 有（行为一致） |
| 待处理入口脉动 | 无 | 有 |
| 图标 hover 描边 | 无 | 无法实现（需 macOS 15） |

### 如何回退 / 调节

偏好设置 → 显示 → 微动效 → **图标动效** 开关。关闭后所有图标动效停止，静态图标正常显示。

## 4. 列表入场级联

**新增文件**：`Sources/DynamicIsland/Views/Components/IslandInteractionEffects.swift`（`CardEntranceCascade`）

### 原来是什么

打开面板时，所有卡片**同时**淡入 + 从右侧滑入：

```swift
// SessionListView.swift:59 —— 原有的卡片过渡
.transition(reduceMotion ? .identity : cardTransition)
```

没有时间差，整体是一块「闪现」。

### 现在是什么

卡片**依次上浮落定**，每张间隔 48ms，上限 420ms：

```swift
CardEntranceCascade(index: index, reduceMotion: reduceMotion, isEnabled: cascadeEntranceEnabled)
```

复刻了 TO-DO Panel 的 `riseIn`（上浮 12px + 淡入 + stagger）。

### ⚠️ 一处容易踩的坑（我按 TO-DO Panel 的经验规避了）

CSS 里这个效果必须写 `animation-fill-mode: backwards`——**延迟期间元素要保持动画起始态**（透明 + 位移），否则会「先完整显示，再跳回起点重播」，产生闪烁。

SwiftUI 没有直接对应物，我用「初始值即起始态」实现等价效果：

```swift
.opacity(hasEntered ? 1 : 0)           // 初始 0，即起始态
.offset(y: hasEntered ? 0 : 12)        // 初始 12，即起始态
```

### 差异对比

| | 原来 | 现在 |
|---|---|---|
| 打开面板 | 所有卡片同时淡入 | 依次上浮，形成节奏 |
| 长列表（10+ 卡片） | 整体闪现 | 延迟封顶 420ms，不会等太久 |
| reduceMotion 开启 | 直接显示 | 直接显示（不变） |

### 如何回退 / 调节

偏好设置 → 显示 → 微动效 → **列表入场级联** 开关。

调节参数在 `IslandMotionTokens.Duration`：`cascadeStagger`（间隔）、`cascadeMaxTotal`（延迟上限）。

## 5. 指针距离感应（**默认关闭**）

**新增文件**：同上（`ProximityLift` / `ProximityLiftModifier`）

### 原来是什么

卡片 hover 是**二值**的——悬停的那张变色，其余不变：

```swift
// SessionListView.swift:300
.onHover { hovering in
    withAnimation(reduceMotion ? nil : IslandMotionTokens.hoverTransition) {
        isHovered = hovering
    }
}
```

### 现在是什么

指针靠近时，附近卡片**连续隆起**（缩放 + 上移），形成 macOS Dock 式的连续曲线：

```swift
let strength = max(0, 1 - distance / radius) ** 2   // 平方衰减
```

**关键点**：遍历**全部**卡片，所以相邻卡片也会被抬起——不是「悬停的那张变大」，而是「一片区域被顶起」。

### ⚠️ 为什么默认关闭（这是我最谨慎的一项）

TO-DO Panel 是 Web 渲染，`transform` 由浏览器合成层处理，逐帧插值**零成本**。SwiftUI 没有等价机制——如果把指针位置写进 `@State`，`pointermove` 每帧都会重新求值视图树。

我做了三层缓解，但**无法完全消除这个成本**：

1. 指针位置由列表容器统一持有，卡片只读不写
2. 仅在位移超过 1pt 时写入状态，过滤亚像素抖动
3. 用 `LazyVStack`，只有可见卡片参与求值

**即便如此，仍会带来额外的 CPU 占用。** 因此我把它设为**默认关闭**，并在偏好设置里明确标注「可能增加少量 CPU 占用」——这个决定应该由你来做，而不是我替你默认打开。

Sapphire 面对同样问题时的选择是：完全绕开 SwiftUI，自己驱动 `CADisplayLink` 并 `CATransaction.setDisableActions(true)`。那是 786 行的引擎，本次没有引入。

### 差异对比

| | 原来 | 现在（开启后） |
|---|---|---|
| 卡片 hover | 二值变色 | 连续隆起 |
| 相邻卡片 | 无反应 | 也被抬起 |
| CPU 占用 | 基线 | **略增**（逐帧状态更新） |
| 默认状态 | — | **关闭** |

### 如何回退 / 调节

- 偏好设置 → 显示 → 微动效 → **指针距离感应**（默认关闭，需手动开启）
- 调节参数在 `IslandMotionTokens.Geometry`：`proximityMaxScale`（默认 1.035，比 TO-DO Panel 的 1.14 保守很多）、`proximityMaxLift`（3pt）、`proximityMinRadius` / `proximityMaxRadius`

**我刻意把增益调保守了**：TO-DO Panel 是 1.14 倍缩放，我只用 1.035——因为面板宽度只有 380pt，1.14 倍会让卡片明显错位。

## 6. 窗口零动画铁律（无需改动）

### 核查结果

TO-DO Panel 的核心踩坑经验是「`setBounds` 一律瞬时，平滑感全在渲染层」。**X Island 已经符合**：

```swift
// NotchWindow.swift:318-321 —— resizeToFit 已经是瞬时 + 禁用隐式动画
CATransaction.begin()
CATransaction.setDisableActions(true)
setFrameDirect(rect, display: display)
CATransaction.commit()
```

且代码注释已记录了原因（AppKit 的 `NSAnimationContext` 分组曾在 `_reallySetFrame:` 中抛异常）。**这一项无需改动**，仅作为核查结论记录。

## 建议的审核顺序

如果你想逐项验收，建议按**可感知程度**从高到低：

1. **触觉反馈** —— 最直接的新体验。试一下权限审批弹出时是否有轻震，以及展开/收起的手感
2. **入场级联** —— 打开面板看卡片是否依次落定
3. **图标动效** —— 待处理卡片的跳转按钮是否脉动
4. **距离感应** —— 需先手动开启，注意观察 CPU 占用
5. **动效令牌** —— 无法直观看出，但可以读 `IslandMotionTokens.swift` 确认参数未被改动

## 需要你决定的两件事

1. **触觉强度语义**：当前「强度」控制事件覆盖范围，非振动幅度。若要真正的幅度分级，需接受私有 API 的上架代价。
2. **距离感应是否保留**：默认关闭，若你实测 CPU 占用可接受，可以改为默认开启。
