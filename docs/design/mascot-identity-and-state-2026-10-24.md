# 吉祥物身份与状态系统

日期：2026-10-24

## 已确认的产品规则

- 软件身份由独立轮廓识别，当前圆角终端机器人仅用于 Codex。
- 用户明确“窗口”指不同聊天／任务标签页，不是 macOS 独立窗口。
- 同客户端的聊天／任务采用固定颜色和编号，状态变化、列表重排及重新打开注册表不改变身份。
- 用户确认：打开任务详情或主动跳转时确认已查看；展开总列表、悬停和自动选择不算。

## 方案取舍

继续共用一张脸只换颜色无法同时表达软件与任务；仅使用官方静态logo又无法承载状态表情。因此采用独立软件轮廓、任务配色及编号、统一状态表情三层编码。这些角色是XIsland自定义图标，不宣称为各软件的官方吉祥物。

## 任务颜色与编号

软件内按首次出现分配递增编号；12色按固定顺序循环，超过12个任务时仍由编号明确区分，不能只靠颜色猜。映射持久保留，不因缓存淘汰改变旧任务身份。身份key使用软件+会话ID；观察来源有namespace与原生taskId时使用两者，避免Roo重载换色。请求发起者覆盖软件时使用该软件的编号空间，避免嵌入式代理撞号。状态、标题、工作目录及列表位置均不参与身份计算。

颜色不是OS窗口归属证明。原有抓取当前焦点窗口的启发式字段不参与此编号。

## 表情与状态

| 真实状态 | 表达 |
|---|---|
| 运行 / 思考 / 压缩 | 睁眼微笑 / 抬眉 / 抿嘴 |
| 等待授权 | 平眉闭口 + 锁 |
| 等待回答 | 睁眼圆口 + 问号 |
| 等待计划审查 | 睁眼圆口 + 文档标记 |
| 错误 | 交叉眼、下弯嘴 + 感叹号 |
| 已完成未查看 | 开心表情 + 持续星标 |
| 普通完成 | 平静微笑 + 勾号 |
| 空闲 / 完成未确认 / 状态未知 | 休息表情；后两者另有省略号／未知标记 |

减弱动画仅停止运动，不移除状态标记。idle与completionUnconfirmed不会伪装成已完成。

## 完成查看状态与存储

新增 `completionNeedsReview`，只在真实完成的新一轮置位；重复结束和历史重放不重新提醒。恢复运行清除旧轮标记，下一次完成重新置位。

显式查看确认绑定该轮完成时间，异步排队或旧历史行不能确认之后的新结果。历史页显示未查看标签并有明确确认按钮；归档确认仅后台更新目标父记录，不加载或重写聊天/事件子记录。现有完成滞留与归档策略保留。

SwiftData追加可选Bool字段，旧nil仅表示没有待查看标记，不宣称用户已经查看。迁移备份编号升为completion-review-v6；旧备份保留。全历史JSON保留true/false/null，旧单会话JSON仍可读取。所有迁移与存储验证使用临时数据库；本机正式库未迁移。

## 入口与可访问性

收起态、会话卡片、阻塞列表及授权/问题/计划面板接入同一身份与状态；保留实际请求发起者的客户端类型。编号同时在图标与卡片标签可见，提示包含软件、任务号、状态和聊天标题。设置 → 显示 → 收起态模块新增“吉祥物识别图例”。

## 常见问题与范围

- 颜色循环是有限调色板设计，编号始终用来消除歧义。
- 普通“已完成”可以是已确认结果，也可以是未记录查看事实的旧历史；不把旧nil称为已查看。
- Codex的原生Stop若仍为完成未确认，则继续显示对应状态，不根据沉默或睡眼猜测完成。
- 本轮未提交、发布或替换本机正式2.0.7，实际动画帧率、VoiceOver朗读和正式升级迁移不属于本轮已验收项。
