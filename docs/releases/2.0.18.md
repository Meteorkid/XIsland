# X Island v2.0.18 — 审批任务图 MCP 与自动接入

日期：2026-11-06

本版把审批上下文地图扩展为可被实时 Agent 写入的本地任务图，并补齐首次授权、客户端自动配置、连接证据和错误恢复。所有 MCP 能力只处理本地任务结构，不能批准命令、回答问题、修改文件或替代原客户端的信任确认。

## 审批任务图 MCP

- 新增 `di-bridge mcp-server --agent <client>` 本地 stdio MCP 服务。
- `approval_graph_get` 返回当前会话已保留节点、待确认提案、批注、revision 和会话 ID。
- `approval_graph_write` 最多提交 32 个任务或步骤节点，支持父子关系、状态、revision 校验和幂等请求 ID。
- Agent 写入的节点先是提案；只有在上下文地图中点击“保留”后才进入已接受任务图，也可以逐节点撤回。
- 待审批节点始终保留高亮；命令、问题、计划和文件操作仍由原客户端及其原有审批流程决定。

## 首次授权与客户端配置

- 首次开启时用一个提示列出将修改的客户端、实际配置路径和完整启动命令。
- 同意按客户端、配置路径和服务器定义分别保存；服务器路径或参数变化后会重新询问。
- 自动支持 Codex、Claude Code、Gemini CLI、Cursor 和 Qwen Code 的用户级配置。
- 只处理实际检测到安装的客户端；不会因为旧配置目录存在就创建孤儿条目。
- Codex 支持绝对路径 `CODEX_HOME`，Claude Code 支持 `CLAUDE_CONFIG_DIR`。
- 同名但非 X Island 自己的条目、用户补充过字段的条目和被改写的 Codex 表不会被覆盖或删除。
- 拒绝授权、关闭上下文地图或快速关闭再开启时，只清理 X Island 的精确自有条目并向最终状态收敛。

## 连接证据与错误提示

- 配置文件存在、客户端 MCP initialize/tools/list/真实请求、hook 活动是三组独立证据。
- MCP 握手绑定到可执行文件与完整参数；App 启动晚于客户端时会保留并绑定握手，完成一次匹配后消费。
- 旧 hook 活动不能把从未加载 MCP 的客户端显示为已接通。
- 后台自动配置失败会显示为“检查失败”，MCP 错误包含目标路径和具体原因。
- “检查并修复”会重新执行配置；成功、关闭来源或卸载客户端后会清除旧错误。

## 实际客户端验收

- Codex：使用已自动写入的用户级配置完成真实 `approval_graph_get`，返回有效 session、revision 和空任务图。
- Claude Code：使用当前可用的 `mimo-v2.6-pro` 完成真实 `approval_graph_get`。
- Cursor Agent：登录后加载服务器、列出两个工具，并完成真实只读 GET。此次使用显式验收会话；Cursor CLI 自身 hook 自动创建会话仍未纳入本版通过范围。
- Gemini CLI 和 Qwen Code 当前未安装可执行文件；OpenCode、WorkBuddy、Kimi、CodeBuddy、Trae 等继续保持手动接入。

Alternatively: **System Settings → Privacy & Security** → scroll to the message about X Island → **Open Anyway**.
