# X Island v2.3.1 — Agent 可读的接入配置

日期：2026-11-27

本次为补丁版本。应用运行时没有改动；新增的是一套面向本机 LLM Agent 的接入配置提示，以及现有接入文档的统一入口。

## English summary

X Island 2.3.1 adds a copy-to-LLM setup prompt library for every integration and places the matching prompt at the end of each existing setup guide. The prompts make an agent inspect the client version, back up and diff the configuration, merge only X Island entries, preserve third-party hooks, and verify a real task without ever auto-approving client trust. Application runtime behavior is unchanged.

## Integration changes

None. The integration matrix remains **35 source entries: 30 active and 5 retired-with-history**. This release adds documentation and onboarding prompts only; it does not add, remove, or re-classify any integration, and it does not merge contract-test results with real-client verification.

## 一、为什么加这一版

此前的接入文档要求用户自己找到客户端配置路径、判断 JSON/TOML 格式、合并 hooks，并在客户端里完成信任确认。文档能解释步骤，但用户仍然要把步骤手工翻译成配置。

2.3.1 把这件事改成“把一段完整任务交给本机 Agent”：

- 每段提示都自带目标客户端、配置路径、桥接命令和验证条件，不需要 Agent 再猜。
- Agent 必须先检查版本、备份、打印 diff，再写入。
- Agent 只能改 X Island 自己的条目，保留第三方 hooks、MCP、模型、JSONC 注释和凭据。
- Agent 不得代替用户确认客户端信任，也不得自动批准权限。
- 配完必须用一条真实只读任务验证；配置文件存在不算接通。

## 二、新增的提示库

新增 [LLM 接入配置提示库](../compatibility/llm-setup-prompts.md)，共 **33 段**可直接复制的完整提示，覆盖：

| 范围 | 客户端 |
|---|---|
| 原生 hooks / settings | Claude Code、Codex、Gemini CLI、Antigravity、Cursor、OpenCode、Factory Droid、Qoder CN、VS Code Copilot、CodeBuddy Code、Qwen Code、Kimi Code、Devin Desktop / CLI、Tabnine 旧版、Cline、GitHub Copilot CLI |
| 插件或宿主扩展 | Kilo Code、Amp、Pi、Trae |
| 手动导入或外部包装 | Aider、Codewhale、WorkBuddy、Kiro CLI V3、豆包工作、Zed / JetBrains ACP、Cody、Continue 旧观察、Amazon Q 旧版 |
| 模型与附加能力 | GLM 多客户端、审批图 MCP、VS Code 伴生扩展 |
| 停用来源 | Hermes、Windsurf、Continue、Roo Code、Amazon Q CLI 的替代说明 |

其中 30 个可接入来源全部有对应提示；5 个停用/合并来源有明确的“不要新建配置、改用继任入口”提示。

- 主 `README.md` 与 `README_zh.md` 增加提示库入口。
- `docs/compatibility/README.md` 增加“让 Agent 直接配置”段落和安装指南条目。

## 四、需要用户手动确认的环节

提示不会替你点客户端里的信任按钮。以下环节仍由用户完成：

| 客户端 | 仍需手动完成 |
|---|---|
| Codex | Composer 的 Review hooks 中只勾选 X Island，再点 Allow selected |
| Trae | 设置 → Hooks 中确认全局配置已列出并打开开关，完全退出后重启 |
| WorkBuddy | 插件管理页“添加市场”选择整个导出目录，核对后启用并信任 |
| 豆包工作 | 新建自定义连接器，选择 STDIO，填入提示给出的命令与参数 |
| Kiro CLI | 用 `kiro-cli chat --v3` 启动，在 `/config` 查看 Hooks 来源 |
| VS Code 伴生扩展 | 从本地 VSIX 安装，必要时重载窗口 |
| 外部 ACP Agent | 在 Zed / JetBrains 中选中包装后的 Agent |

这些步骤被刻意保留为人工确认，避免 Agent 在用户不知情时扩大权限或信任范围。

## 六、升级与安装

- 版本：`2.3.1`。
- 系统要求：macOS 14 Sonoma 及以上。
- 运行时行为、历史库位置、审批队列和审计格式与 2.3.0 相同。
- 该包仍为 **ad-hoc 签名**，没有 Developer ID Team ID。2.3.0 的新更新器会按 fail-closed 规则拒绝 ad-hoc 更新包，因此**不会出现可用的自动更新按钮**；请手动下载 DMG 覆盖 `/Applications/X Island.app`。
- 覆盖安装后仍需重新授予辅助功能权限；未授权时「继续下一步」仍复制指令到剪贴板，手动 ⌘V 后回车即可。

## 原有使用规则

安装包继续提供免费下载，首次启用联网后开始完整的 **14 天试用**。用户可以选择一个月、一年或永久授权，每份产品授权最多同时使用 **3 台设备**，支持解绑换机。

## macOS Gatekeeper

If macOS blocks the app after installing from the DMG, run:

```bash
xattr -cr /Applications/X\ Island.app
```

Alternatively: **System Settings → Privacy & Security** → scroll to the message about X Island → **Open Anyway**.

## 辅助功能权限

「继续下一步」需要辅助功能权限才能自动粘贴。应用内 **设置 → 权限** 集中展示状态并提供授权入口；更新版本后需重新拖入一次（ad-hoc 签名的固有限制，应用会自动清理旧条目）。未授权时指令仍复制到剪贴板，手动 ⌘V 后回车即可发送。
