# X Island v2.3.2 — 工程质量与安全加固

日期：2026-11-28

本次为补丁版本。没有新增用户界面功能或 AI 客户端接入；生产环境的正常输入行为保持不变，主要变化是补齐发布与质量门禁，并让三个异常输入路径安全失败而不是崩溃。

## English summary

X Island 2.3.2 is an engineering-hardening patch. It adds repeatable documentation, Swift runtime-safety, loop-state, release-preflight and unified quality gates; hardens three runtime failure paths without changing valid production inputs; and ships no new AI client integrations. The application is still ad-hoc signed, so the existing updater remains fail-closed and this release must be installed manually.

## Integration changes

None. The integration matrix remains **35 source entries: 30 active and 5 retired-with-history**. This release does not add, remove, or re-classify any integration, and it does not merge contract-test results with real-client verification.

## 一、为什么发布 2.3.2

2.3.1 只更新了接入文档和提示库。之后完成的 16 轮工程迭代没有发布，其中既有可验证的运行时安全修复，也新增了文档、Swift 安全、循环状态和统一质量门禁。2.3.2 把这些改动收进一个可安装的补丁包。

这一版不承诺新的产品功能，重点是减少“配置或输入异常导致进程直接退出”的概率，并让后续发布有可重复的检查入口。

## 二、运行时改动

### 1. ACP 配置命令安全转换

`ACPCustomAgentConfiguration` 不再使用 `result["command"] as! String`。当 ACP 配置中的 `command` 不是字符串时，解析会按非法配置处理并拒绝，而不是崩溃。合法字符串输入行为不变。

### 2. SSH 输入校验 fail-closed

`SSHInputValidator` 的 4 个静态 `NSRegularExpression` 从 `try!` 改为可失败编译。若正则因未来编辑变成非法 pattern，Host、User、RemotePath 校验会返回 `false`，随后抛出对应的 `SSHValidationError`，不会在静态初始化时终止进程。

这是安全优先的预期行为：非法 pattern 会导致 SSH 操作被拒绝，而不是接受未校验输入。

### 3. 测试 socket 目录回退

`DISocketConfig.socketDir` 不再对非法测试目录调用 `preconditionFailure`。测试模式下若 `X_ISLAND_TEST_RUNTIME_DIR` 非法，会回退到 `/tmp/xi-test-<pid>` 独立临时目录；生产路径仍为 `<home>/.xisland`。

该回退按 PID 生成。如果主进程与 bridge 都以非法测试目录启动，它们会落在不同 socket 路径，表现为测试无法连接，而不是提前崩溃。测试启动前仍应通过 `AppTestConfiguration` 拒绝非法隔离配置。

## 三、质量与发布工具

新增或完善了以下只读检查：

- 文档质量门禁：Markdown 围栏、仓库内相对链接、发行说明章节、VERSION/Cask 一致性、LLM 提示覆盖。
- 发布预检：VERSION、Cask、发行说明、`SHA256SUMS.txt` 和实际 DMG 的交叉校验。
- Swift 安全 token 门禁：扫描 `try!`、`fatalError(`、`as!`，已复核例外必须带同行豁免标记。
- 循环状态校验：校验 `STATE.md` 必需字段、状态和轮次一致性。
- 统一质量门禁入口：`bash Scripts/run-quality-gates.sh`，可用 `--build` 追加 release build。
- GitHub Actions 文档工作流已接入文档、Swift 安全和循环状态的正负向检查。

这些工具不改变应用运行时行为，但让后续版本可以在本地用同一条命令复现发布前检查。

## 五、升级与安装

- 版本：`2.3.2`。
- 系统要求：macOS 14 Sonoma 及以上。
- 历史库位置、审批队列和审计格式与 2.3.1 相同。
- 该包仍为 **ad-hoc 签名**，没有 Developer ID Team ID。现有更新器会按 fail-closed 规则拒绝 ad-hoc 更新包，因此**不会出现可用的自动更新按钮**；请手动下载 DMG 覆盖 `/Applications/X Island.app`。
- 覆盖安装后仍需重新授予辅助功能权限；未授权时「继续下一步」仍复制指令到剪贴板，手动 ⌘V 后回车即可。

## 原有使用规则

安装包继续提供免费下载，首次启用联网后开始完整的 **14 天试用**。用户可以选择一个月、一年或永久授权，每份产品授权最多同时使用 **3 台设备**，支持解绑换机。

## macOS Gatekeeper

If macOS blocks the app after installing from the DMG, run:

```bash
xattr -cr /Applications/X\ Island.app
```

Alternatively: **System Settings → Privacy & Security** → scroll to the message about X Island → **Open Anyway**.

## 辅助功能权限

「继续下一步」需要辅助功能权限才能自动粘贴。应用内 **设置 → 权限** 集中展示状态并提供授权入口；更新版本后需重新拖入一次（ad-hoc 签名的固有限制，应用会自动清理旧条目）。未授权时指令仍复制到剪贴板，手动 ⌘V 后回车即可发送。
