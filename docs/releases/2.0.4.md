# X Island v2.0.4 — 双岛切换与显示可靠性修复

本次修复了 X Island 与 XNook 切换时“目标没有打开，当前岛却消失”的问题，重点完善启动、显示确认、失败恢复和连续切换。建议同时更新到 [XNook 1.3.18](https://github.com/Meteorkid/XNook/releases/tag/v1.3.18)。

## 切换目标未运行时，会先尝试打开

- 改为按目标应用的正式安装路径打开显示命令，减少构建副本、备份 App 或默认 URL 处理器导致的误跳转。
- 保留当前岛，直到确认目标应用的实际岛体已经出现在屏幕上，才让当前岛让位。
- 为目标缺失、启动失败及 8 秒未显示增加了保留／恢复处理。
- 阻止了重复手势或点击重复启动目标应用。

## 首次使用也能完成双向切换

- 修复了依赖对方先运行并登记旧协议版本的问题，安装包已声明切换能力时即可尝试打开。
- 修复了默认 URL 处理器与实际安装位置不一致时，切换入口被错误判为异常的问题。
- 保留了应用启动早期收到的显示命令，窗口创建后会继续处理。
- 将启动显示判断改为检查对方岛体是否可见，避免“进程在后台运行”被当成“已经显示”。

## 连续切换和桌面变化更稳定

- 为每次切换增加了独立请求标识，已取消请求的启动回调、轮询和超时结果不会再影响新操作。
- 为跨应用隐藏通知增加了来源及显示时间校验，避免旧通知隐藏刚刚重新显示的岛体。
- 修复了旧全屏检查结果覆盖显式显示、较新检查或已关闭的全屏隐藏设置的问题。
- 修复了上一轮计时器过早解除新切换保护的问题。
- 按两款应用各自的岛体层级确认窗口，排除了 X Island 设置窗口被误认为岛体的情况。

## 实际验证

最终源码全量 Swift 测试共 1,445 项：1,431 通过、14 项按条件跳过、0 失败；最终包另通过 127 项桥接场景、11 个 WorkBuddy 事件及隔离的 Codex 合成生命周期核验。

| 场景 | 验证结果 |
| --- | --- |
| X Island → 未运行的 XNook | 启动目标，目标岛出现后来源岛隐藏 |
| XNook → 未运行的 X Island | 启动目标，目标岛出现后来源岛隐藏 |
| 两款都运行时切到 XNook | 完成切换，两款进程保持运行 |
| 两款都运行时切回 X Island | 完成切换，两款进程保持运行 |

上述实测使用与本次发行相同的 Swift 源码构建，四轮各约 18 秒，合计 654 次窗口可见性采样，未采到双岛同时隐藏。该记录不是 FPS 测量；触控板手势未单独重新验收，失败与超时恢复由隔离回归覆盖。

本次升级未修改历史数据结构；本地更新后原有历史记录全部保留，数据库完整性核对通过。测试细节与发行包信息见 [2.0.4 发行验证摘要](https://github.com/Meteorkid/XIsland/blob/v2.0.4/docs/compatibility/release-verification-2.0.4.json)。

## 更新建议与发行范围

1. 将 X Island 更新到 2.0.4，同时将 XNook 更新到 1.3.18。
2. 正常退出旧版本后替换应用，再打开任意一款。
3. 在“设置 → 联动”点击“切换到对方”，或继续使用已启用的横滑切换。

本次提供 macOS 14 及以上的 Apple Silicon 安装包；Windows 本轮没有改动，配套 VS Code 扩展保持 1.0.0。首次客户端信任仍由用户在对应 AI 客户端确认，本次更新不会代为授权。

安装包使用 ad-hoc 签名，尚无 Apple Developer ID 签名或公证。VoiceOver 朗读、持续实际 FPS、外接多屏和完整客户端闭环仍按原计划验收，不随本次切换修复扩大完成范围。

## macOS Gatekeeper

If macOS blocks the app after installing from the DMG, run:

```bash
xattr -cr /Applications/X\ Island.app
```

Alternatively: **System Settings → Privacy & Security** → scroll to the message about X Island → **Open Anyway**.
