# X Island v2.0.3 — 授权引导与接入窗口修复

本次更新让“待授权”有清楚的下一步：设置页直接显示操作方法，打开授权步骤时能找到对应软件，客户端无法打开时也会给出明确反馈。

## 更容易找到授权方法

- 在 Codex“待授权”下新增了提示，明确右侧勾选只表示启用接入，仍需在 Codex 中确认信任。
- 新增了“查看授权步骤”入口，并直接展示 Review hooks → 选择 X Island 项 → Allow selected 的操作路径。
- 将授权窗口内的三个步骤改为默认可见，包含审查钩子、确认所选项，以及启动任务后重新检查接通状态。
- 将操作按钮明确标为“打开 Codex 确认”，并补齐了中英文提示。
- 说明了未变配置的有效授权会被记住，配置变更或撤销授权后需要重新审阅。

## 修复窗口定位与状态变化

- 修复了“查看授权步骤”只打开软件总列表、用户仍需寻找 Codex 的问题。
- 支持在已有窗口中重新定位同一软件，并自动展开目标所在的分组。
- 支持 Codex 转为“等待活动”“已接入”或已关闭后的定位，展示当前状态。
- 保留了普通菜单打开窗口时的滚动位置，后台回查不会反复把列表拉回目标行。

## 客户端启动失败也有反馈

- 为桌面应用未找到和启动失败分别增加了可操作的提示。
- 修复了仅检测到 CLI 时，点击“打开客户端”却静默跳到网页的问题，完整指南改为由用户明确选择。
- 启动期间增加了重复点击保护，避免重复发起客户端启动。
- 关闭窗口或重新检查后会清除旧反馈，迟到的成功或失败结果不会覆盖新的操作。
- 旧的启动错误不会继续显示在已经接通的软件上。

## Codex 首次授权

1. 在 X Island 的设置 → 代理中，点击 Codex 下方的“查看授权步骤”。
2. 点击“打开 Codex 确认”，在 Codex 输入区进入 **Review hooks（审查钩子）**。
3. 核对命令，**只选择 12 条 X Island 钩子**，点击 **Allow selected（允许所选项）**。
4. 开始一条任务，再回 X Island 点击“重新检查”；收到真实活动后才会显示已接入。

“打开客户端”和“启用接入”均不会代替用户授予信任；不要对包含其他插件的整个来源使用 Trust all。详细说明见[软件接入说明](https://github.com/Meteorkid/XIsland/blob/v2.0.3/docs/compatibility/README.md)。

## 验证与发行范围

- 1,400 项 Swift 测试通过、0 失败，另有 5 项按需性能/长稳入口未重复运行；发布前核对了全部 Swift 源码与测试快照一致。
- 150 项接入、授权状态和窗口相关回归通过，并检查了 37 张引导及定位快照中的代表场景。
- 通过隔离窗口验证实际滚动，通过启动替身验证失败、重试、重复点击和迟到结果；未代替用户操作真实 Codex 信任。
- 最终安装包另行核对版本、arm64 架构、代码签名、图标、CLI 和校验值，并验证包内桥接与合成事件链路。
- 本次发布 macOS 14 及以上的 Apple Silicon 安装包，Windows 本次无变更，配套 VS Code 扩展仍为 1.0.0。
- VoiceOver 朗读、实际连续 FPS、外接多屏和完整真实客户端闭环仍保留原有待验范围。
- 安装包沿用 ad-hoc 签名，尚无 Apple Developer ID 签名或公证。

详细验证见 [2.0.3 发行验证摘要](https://github.com/Meteorkid/XIsland/blob/v2.0.3/docs/compatibility/release-verification-2.0.3.json)。

## macOS Gatekeeper

If macOS blocks the app after installing from the DMG, run:

```bash
xattr -cr /Applications/X\ Island.app
```

Alternatively: **System Settings → Privacy & Security** → scroll to the message about X Island → **Open Anyway**.
