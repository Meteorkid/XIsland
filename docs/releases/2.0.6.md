# X Island v2.0.6 — 安全加固与动效手感修正

本次集中加固更新通道与本地连接的安全性，并修正展开／收起的动效取向、为收起过程加上兜底保护。

> 若你正在使用 2.0.5，本次更新不影响「最近任务数量」等已有设置，偏好项与历史数据全部保留。

## 安全加固

这一版修复了若干在源码审计中发现的问题，其中一项影响所有在线更新的用户。

### 更新通道

- 安装更新前新增发布者身份校验：校验下载包的签名身份是否与官方一致，而不只是校验签名本身是否自洽。
- 更新包的下载来源收窄为官方仓库域名，非官方来源的下载地址会被拒绝。

### 本地连接

- 新增对端进程身份校验，仅接受来自 X Island 自身调用链的连接，并检测桥接程序是否被替换或篡改。
- 新增并发连接上限、读取超时与交互式连接空闲超时，避免大量空连接堆积导致顶部面板失去响应。
- 桥接工具改为按内容校验并自动修复：文件被改动时会重建，不再依赖修改时间判断。
- 相关配置目录权限收紧为仅当前用户可访问。

#### 发布前修复

对端校验在开发过程中出现过两处会让面板**完全失联**的缺陷，都在发布前发现并修掉了。记录在此，因为它们的表现（面板毫无反应）与「校验生效」很像，容易被误判为正常拦截：

1. **读错了系统常量。** 最初用 `0x005` 读取对端 UID，但这个值在 macOS 上是 `LOCAL_PEEREUUID`（对端 UUID），不是 UID —— 系统里根本没有 `LOCAL_PEEREUID`。结果是拿对端 UUID 的前 4 字节去和真实 UID 比较，永远不相等，**每一条连接都被判为不可信并关闭**。已改用 `getpeereid`。
2. **把「对端已退出」当成「不可信」。** 除授权审批外的 hook 都是「发完就走」——桥接程序写入数据后立刻退出。服务端 `accept` 到时对端进程常常已经消失，此时拿不到它的 PID 与可执行路径。原逻辑把这种情况直接判为不可信并关闭连接，导致**所有非交互事件都无法送达**。现在路径取不到时按 UID 放行（UID 由内核快照，仍然可靠）。

两处都补了回归测试，并新增了一项端到端校验：合成生命周期事件 → 包内桥接程序 → 隔离运行的应用，逐条确认事件真的被处理。

### 终端跳转

- 调用外部终端命令时改为使用受控的环境变量，不再继承当前进程环境。
- 统一转义跳转时传入的特殊字符，消除路径中引号或换行导致的异常。

## 动效与交互

### 展开与收起的手感

- 修正了展开／收起的动效取向。此前展开过程偏「稳」，几乎看不到回弹；而收起过程会有一点多余的抖动。现在两者对调：展开保留一次明显的回弹，显得更有生命感；收起干脆落定，不再有尾部抖动。
- 三档动效强度均按此取向调整，可在「设置 → 显示 → 动画强度」切换。

### 收起看门狗

- 新增收起过程的兜底保护。收起动画若因异常未能正常收尾，面板会在约 1 秒内自动复位。此前这种情况会让面板停在错误尺寸且不再响应，只能重启应用。
- 正常情况下不会触发，属于保险机制。

### 触觉反馈

- 新增触觉反馈，覆盖授权审批、任务失败、等待输入、展开收起与任务切换。
- 可在「设置 → 显示 → 触觉反馈」关闭，或调整触发范围。
- 使用系统公开接口实现，不涉及私有 API。

### 其他界面增强

- 待处理任务的跳转按钮新增脉动提示，工具执行完成时新增弹跳反馈，均可单独关闭。
- 任务列表新增入场级联：打开面板时卡片依次上浮出现，而非整体闪现。

## 如何使用

安全加固与动效修正默认生效，无需设置。

触觉反馈与界面动效可在设置中调整：打开 X Island 设置，进入「显示」，向下可找到「微动效」与「触觉反馈」两个分组。

## 验证与发行范围

本次验证包括最终发行源码的完整 Swift 回归，以及更新通道校验、本地连接身份校验、动效参数与看门狗判定逻辑的单元测试。最终安装包另行核对版本、架构、签名与校验和。

最终发行源码执行了 **1495 项 Swift 测试，1479 项通过、16 项按条件跳过、0 失败**。

## 已知限制

- 更新通道的发布者身份校验已具备完整校验能力，但**当前发布包仍为本地签名**，尚未启用严格比对。要完全启用需申请 Apple 开发者证书并重建发布流程。这是本次安全加固中唯一未完全生效的一项。
- 本地连接的身份校验提高了接入门槛，但**不是强认证**，有两处已知边界：
  - 同一用户下的任何进程都能通过 `/bin/sh -c` 之类的系统 shell 发起连接并通过校验 —— 放行系统 shell 是保持集成可用的必要条件。
  - 由于「发完就走」的 hook 在服务端看来对端已退出，攻击者同样可以抢先退出来跳过可执行路径校验，此时仅剩 UID 判定。
  - 实际收益是：拦截跨用户连接，并在路径可得时拦截未走既定调用链的进程、检测桥接程序被篡改。要做到强认证需改造各客户端的接入调用链，涉及全部接入方式的回归验证。
