# X Island v2.3.0 — 审批闭环、精确跳转与接入收口

日期：2026-11-27

本次为中版本更新。从 2.2.0 到 2.3.0，重点不是再增加一个状态灯，而是把「Agent 要做什么」变成可检查、可干预、可追溯的审批闭环，并把「点会话卡片」从按应用猜测推进到按终端 pane、聊天会话和唯一可访问性行定位。

## English summary

X Island 2.3.0 turns approvals into a reviewable, auditable loop: inline diff previews, deny reasons, edited-input approval, interrupt, session-scoped exact Bash rules, and lifecycle-based card clearing. It also makes session jumps follow actual terminal panes and chat routes, adds Doubao Work, Kilo Code and Antigravity integrations, and moves the history store to an app-owned location with migration, backup pruning and maintenance.

## Integration changes

**Added**

- **Antigravity (App / CLI / IDE)** — named global hooks in `~/.gemini/config/hooks.json`; five official events contract-tested; `PreToolUse` returns neutral `allow` only, no island approval; real-client loading pending.
- **Kilo Code CLI / VS Code** — native global plugin on the OpenCode core; plugin source and adapter contracts passed; observation only, permissions/questions/cancel stay in Kilo; real CLI/extension loading pending.
- **Doubao Work** — STDIO custom connector using `xisland_activity`; observation only, no native hooks, approvals, questions or cancel; connector disconnect ends observation; real-client loading pending.

**Re-classified or retired**

- **Gemini CLI** — individual plans ended 2026-06-18; only enterprise and paid API Key routes remain.
- **Windsurf** — renamed Devin Desktop on 2026-06-02; history retained, new setups use Devin Desktop.
- **Amazon Q CLI** — rebranded Kiro CLI on 2025-11-17; history only.
- **TRAE Work** — merged into Doubao Work in 2026-08.
- **Qoder CN** — formerly Tongyi Lingma, renamed 2026-05-20.
- **Continue** — acquired by Cursor in 2026-06; retired as an entry point.
- **Roo Code** — shut down 2026-05-15; retired; use Cline or Kilo Code.
- **Tabnine** — acquired by Tricentis on 2026-07-30; 6.x CLI is an OpenCode branch, auto-config covers the legacy CLI only.
- **Cody** — enterprise-only until end of support on 2027-01-31.

The matrix now has **35 source entries: 30 active and 5 retired-with-history**. Contract tests and real-client verification remain separate claims.

## 一、审批：从一次性弹窗变成可审计闭环

### 1. 先看改动，再决定

Claude 兼容 hook 的 `Edit` / `Write` / `MultiEdit` / `NotebookEdit` 审批卡会从 `tool_input` 生成只读预览：

- 旧行红色 `-`，新行绿色 `+`，显示 `+N −M` 计数。
- `replace_all` 和多修改分块分别标记；`NotebookEdit` 的 `replace` / `delete` 模式也会显示。
- `Write` 明确提示「完整写入内容，可能覆盖现有文件」，不会把它说成追加。
- 请求到达时解析一次并缓存到 `PendingPermission.diffPreview`；UI 重绘不重复解析，也不读取目标文件。
- 预算为 200,000 字节输入、8 个修改块、每侧 12 行、单行 400 字符；超出显示截断提示，完整原文仍在原始工具参数中。

它只用于知情裁决，不参与 allow/deny，也不冒充完整 unified diff。没有真实行号、未修改上下文或二进制判断。

### 2. 五种明确的裁决方式

Claude Code 的审批卡现在提供：

| 操作 | 回传字段 | 适用边界 |
|---|---|---|
| 拒绝 | `decision.behavior = deny` | 所有来源 |
| 拒绝并说明 | `deny` + `decision.message` | 仅 Claude Code；原因上限 1,000 字符，空白退回普通拒绝，不写入审计账本 |
| 修改后批准 | `allow` + `decision.updatedInput` | 仅 Claude Code；Bash 编辑 `command` 并保留其余字段，其他工具编辑完整 JSON 对象；上限 64,000 字节，必须是 JSON 对象，非法时保持卡片，绝不降级批准原命令 |
| 拒绝并停止本轮 | `deny` + `decision.interrupt = true` | 仅 Claude Code；可与拒绝原因同时使用；只停止当前回合，不承诺终止后台子代理或已脱离 shell 的进程 |
| 本会话允许此命令 | `allow` + `decision.updatedPermissions` | 仅 Claude Code、仅 Bash、仅主代理；命令必须完全相同、无 `*`、无换行、非空且不超过 2,000 字节；只写 `destination = session` 的一条 `addRules` |

「本会话允许」不写 `localSettings` / `projectSettings` / `userSettings`，不跨会话、不自动裁决。子代理审批卡不显示该入口，避免子代理替父会话扩权。宿主自身的 deny/ask 优先级仍然生效。

### 3. 不裁决，也不假装裁决

- 用户超时、关闭或放弃时，Claude 兼容来源输出 `{}` + exit 0；Cursor 输出 `{"permission":"ask"}` + exit 0。
- 空决策表示「不裁决」，不是自动批准，也不是伪造拒绝。
- Cursor 3.15.6 的 `cursor-agent-exec` 只消费 `deny` / `ask`，所以岛上只提供「拒绝」与「交回 Cursor 确认」，不显示会骗人的「允许」。
- 同一会话的权限请求进入队列，上限 16；当前请求解决后自动晋级下一个。重复或溢出请求交回客户端原生流程。
- 每个请求带 310 秒租约，与 hook 的 300 秒超时对齐；过期项清理，未过期队列项继续晋级。

### 4. 子代理与生命周期

- Claude 子代理的 `agent_id` 随 `PermissionRequest` 进入父会话，卡片显示「子代理 · agent-id」；同名工具请求不再被误去重。
- `PreToolUse` 的 `tool_use_id` 与规范化 `tool_input` 哈希用于关联没有 ID 的 `PermissionRequest`；对应 `PostToolUse` / `PostToolUseFailure` 到达时精确清卡，记为 `nativeResolved`，不按整个会话清空。
- Claude `Stop` / `SubagentStop` 到达时，按 `originAgentID` 清理当前和队列中的 Claude 权限请求，记为 `nativeTurnEnded`；主代理与子代理互不误清，Cursor 请求不参与。
- 每会话最多保留 12 条工具关联线索，10 分钟内有效；歧义、缺 ID 或事件丢失时不猜，保留租约兜底。

### 5. 本地审批审计账本

- 默认写入 `~/.xisland/approval-audit.jsonl`，append-only JSONL，文件权限 `0600`。
- 每条记录包含决定类型（批准 / 拒绝 / 交回原生 / 超时 / 原生已处理 / 轮次结束 / 取消）、会话、Agent、工具、子代理来源、延迟、`payloadHash`、`previousHash` 和 `hash`。
- `payloadHash` 只存 `tool_input` 的 SHA-256，不复制完整命令或文件内容；拒绝原因也不写入账本。
- 偏好设置「审批记录」页读取最近 500 条，支持按决定过滤、按工具 / 会话 / 来源搜索、显示链状态和断裂行号，并可导出原始 JSONL。
- 链校验逐行解码、重算哈希、校验 `previousHash` 等于前一条 `hash`；首个非空记录带非空 `previousHash` 时报 `missing predecessor`。
- 它只证明当前文件从第一行到当前行自洽，不是外部防篡改证据；能改 `~/.xisland` 的人也能重写整条链。

### 6. 计划审查与 Cursor 边界

- Claude Code、Qwen Code、Qoder CN、Trae 的 `ExitPlanMode` 请求映射为计划审查；批准时回传原始 `tool_input` 作为 `updatedInput`，避免只显示允许却仍弹原生确认。
- Cursor 配置覆盖 11 类 hook 事件，其中 `beforeShellExecution` / `beforeMCPExecution` 是权限入口；观察事件仍固定放行，权限事件保留 bridge 的等待和 JSON 决策，连接失败时回 `permission: ask`。

## 二、会话跳转：从按应用猜到按 pane / chat 定位

### 1. 终端进程树

hook 进程沿父链解析控制 TTY，2 秒超时、带环路保护，只接受 `/dev/tty*`。这是后续 Ghostty、tmux 和 VS Code 终端定位的共同基础。

### 2. 终端与复用器

| 场景 | 路由 | 失败边界 |
|---|---|---|
| iTerm2 / Terminal / WezTerm / Kitty | 会话自带 ID 时直接定位标签 | 没有 ID 或目标不存在时降级 |
| tmux | `switch-client → select-window → select-pane`，再按 `client_tty` 聚焦外层标签 | tmux 改写 `TERM_PROGRAM` 时按 pane 判断，不信任旧会话 ID |
| Ghostty | AppleScript 优先按 TTY 匹配；TTY 不可用时只用唯一 CWD | 匹配数不为 1 直接失败，不激活整个应用 |
| Warp | 只读 SQLite `WarpPaneResolver`，按 cwd 查 pane / tab / window，再用 `Cmd+1…9` 切标签 | 只允许唯一 pane、单窗口、存在快捷键的标签；歧义或多窗口拒绝 |
| VS Code 集成终端 | 1.1.0+ 伴生扩展 `vscode://meteorkid.xisland-vscode/focus`，按 tty → pid → 唯一 cwd 匹配已存在终端 | 不新建终端、不发命令、不读输出 |

### 3. 桌面与 IDE 会话

- Claude Desktop Code / Cowork 读取应用自己的 `claude-code-sessions` / `local-agent-mode-sessions` 索引，把 CLI `session_id` 映射为 `local_*`，生成 `claude://claude.ai/epitaxy/<id>` 或 `claude://claude.ai/cowork/<id>`。
- Claude Code VS Code 只在 `.completed` 状态使用官方 `vscode://anthropic.claude-code/open?session=<uuid>`。活跃或等待中的会话不直接用该链接，因为上游 #65542 记录忙碌会话可能被当成找不到而新建空白对话；此时改为项目级打开 + 严格可访问性行定位。
- 其他 IDE 先激活应用并打开项目目录，再在 AX 树里只接受可按下、已启用、位于列表 / 树 / 表格 / 标签组 / 滚动容器内的控件。标题完全相等优先，包含匹配至少 4 字符；同名多个返回 `.ambiguous`，绝不点第一个。
- `notFound` 重试 2 次，`.ambiguous` 不重试；新增结果语义覆盖 `companionRequested`、`applicationRaised`、`accessibilityDenied`、`conversationAmbiguous`。

这次没有解决「所有 Agent 的聊天级精准跳转」这个不存在的能力：没有稳定会话标识或宿主路由的客户端仍然只能项目级打开，并明确提示，而不是假装已定位。

## 三、接入矩阵：新增三条、停用五条

## 四、数据与稳定性

### 1. 历史库搬进应用专属目录

- 生产历史库从通用的 `~/Library/Application Support/default.store` 迁到 `~/Library/Application Support/XIsland/XIsland.store`，避免与非 sandbox 的 SwiftData 应用重名，也让卸载清理能定位。
- 迁移在 ModelContainer 打开前执行：使用 SQLite 在线备份（包含 WAL 已提交内容）生成独立文件，`PRAGMA integrity_check` 通过后再原子移动；旧库直到新库校验成功后才删除。
- 迁移失败时优先选择仍然存在的库；两者都不存在时回新路径新建空库，不丢已成功迁移的数据。
- 旧根目录的 `HistoryBackups` 合并进应用目录；旧 `default.store.pre-*` 恢复点改名为 `XIsland.store.pre-*`。只有全部文件移走或目标已存在才删除旧目录，避免移动失败丢备份。
- 恢复点按总大小保留最近一份，其余按修改时间从旧到新删除，默认预算 2GB；最新一份无论多大都保留。
- 启动前检查 SQLite freelist：文件至少 50MB 且空闲页至少 256 时才 `VACUUM`；拿不到独占锁就跳过，等下次启动，避免每次启动重写全库。
- 长期未结束的 active / idle / error 会话在超过 `max(保留天数 × 3, 90)` 天后清理；等待交互的会话不在此列。

### 2. 自动更新不再只验「签名自洽」

- `codesign --verify` 只能证明资源封印与签名匹配，ad-hoc 自签名同样能通过；原实现未配置 Team ID 时会接受这种包。
- 现在更新包必须带 Team ID，且与 Info.plist 的 `XIslandUpdateTeamIdentifier` 或当前运行 App 的 Team ID 一致；当前 App 为 ad-hoc 且没有可信 Team ID 时直接拒绝，fail closed。
- 安装脚本同样执行 Team ID 校验，ad-hoc 或缺失 Team ID 一律拒绝，不留空守卫绕过路径。
- 发布构建可用 `X_ISLAND_UPDATE_TEAM_ID` 写入 Info.plist；未配置时不会把 ad-hoc 包当成可信更新源。

### 3. 其他修复

- **AF_UNIX 短连接丢帧**：对端写完即关闭时，macOS 对 `SO_RCVTIMEO` 返回 `EINVAL`；`readFramedMessage` 在读取前退出，审批响应与观察消息会整帧丢失。改用 `poll` 承担超时并以 `MSG_DONTWAIT` 读取；`VSCodeObservationCommand` 的关闭等待同样去掉该选项，并补 socketpair 回归测试。
- **Antigravity 应用标识**：`TerminalJumpManager` 原先使用 `com.antigravity.Antigravity`，与实际安装包 `com.google.antigravity` 不符，已修正。
- **Cursor 权限 hook 被观察模板覆盖**：旧配置把 `beforeShellExecution` / `beforeMCPExecution` 映射为 `preToolUse` 并丢弃 bridge 输出后固定放行；新配置保留等待与权限 JSON，连接失败才回 `permission: ask`。
- **ExitPlanMode 批准被原生确认覆盖**：PermissionRequest 的 allow 缺少 `updatedInput` 时 Claude Code 会忽略 hook 决定；现按原始 `tool_input` 回传。
- **测试目标无法编译**：`TaskAttentionBounceTests` 仍断言已移除的 `Pose.rotation`，`TerminalAppDetectionTests` / `SessionJumpRoutingTests` 的 `SessionSnapshot` 缺少 `title`；已按当前源码修正，测试目标恢复可编译。
- **UI 测试与生产 App 冲突**：`test-ui.sh` 默认拒绝在生产 X Island 正在运行时启动，避免两个实例争抢刘海窗口导致超时；仅在显式设置 `X_ISLAND_UI_TEST_ALLOW_RUNNING_APP=1` 时放行。
- **插件归属**：Kilo 插件进入统一的源归属校验，用户改过的文件在修复/卸载时保留。

「继续下一步」需要辅助功能权限才能自动粘贴。应用内 **设置 → 权限** 集中展示状态并提供授权入口；更新版本后需重新拖入一次（adhoc 签名的固有限制，应用会自动清理旧条目）。未授权时指令仍会复制到剪贴板，手动 ⌘V 后回车即可发送。
